# Лекция 07 — Entity resolution и графы связей

> Оригинальное название: «Entity resolution та зв'язки: від сутностей до графа».

## О чём лекция

Как понять, что разные записи из разных источников — один и тот же реальный объект (entity resolution, ER),
как не склеить двух однофамильцев и как довести данные до графа связей с оценкой уверенности.
Практическая часть — три инструмента: **Flowsint** (технический графовый OSINT), **Neo4j + OpenSanctions**
(санкции, PEP, офшоры) и **OSINT Copilot** (десктопное приложение с AI-агентом).

> [!note] Источник
> Слайды 27–29 и 35–37 — скриншоты Flowsint / Neo4j Browser / видео-демо, в конспект не переносились.

## Проблема: «один и тот же, но разный»

Из 8 источников получено: «Іван Петренко, CEO TechUA» (LinkedIn), «I. Petrenko, head of TechUA Ltd» (реестр),
`ivanp_kyiv` (GitHub), email, `@ivan_tech_ua` (Telegram), телефон (WhatsApp), «Іван П., директор» (суд),
`IvanUA` (крипто-форум). Один человек или восемь записей?

**Entity Resolution** — процесс установления, что разные записи из разных источников относятся к одному
реальному объекту.

## Сущности и граф

**Граф = сущности (узлы) + связи (рёбра) + атрибуты + вес.**

| Тип сущности | Примеры | Ключевые атрибуты |
|---|---|---|
| Person | человек, псевдоним | имя, дата рождения, фото, ник |
| Organization | компания, НКО, госорган | название, идентификационный код, юрисдикция |
| Location | адрес, координаты | GPS, страна, индекс |
| Artifact | email, IP, домен, телефон | значение, протокол, регистратор |
| Event | встреча, транзакция | дата, участники, место |
| Crypto-asset | кошелёк, NFT | адрес, сеть, баланс |

## Три метода ER

1. **Детерминистический (точное совпадение):** тот же email → один человек (10/10); тот же телефон (9/10);
   тот же хэш фото → одно изображение (10/10).
2. **Вероятностный (fuzzy match):** «Іван Петренко» + «I. Petrenko» + общая компания → вероятно тот же (7/10);
   варианты транслитерации + совпадающая должность → 6/10.
3. **AI-подход (семантический):** эмбеддинги (сходство записей), LLM (контекстные подсказки),
   Graph Neural Networks (предсказание скрытых связей). Пример из лекции: KnowCTI — ~93% точности
   извлечения сущностей из CTI-текстов (2025).

## Идентификационные якоря

| Якорь | Уникальность | Постоянство | Примечание |
|---|---|---|---|
| Email | высокая | высокая | ключ к большинству сервисов |
| Телефон | высокая | средняя | меняется реже, чем кажется |
| Ник | средняя | высокая | люди очень последовательны (в среднем один ник на 20–40 платформах) |
| Фото профиля | высокая | средняя | обратный поиск изображений |
| Крипто-кошелёк | очень высокая | высокая | неизменный публичный адрес |

**Слабые якоря** (нужно подтверждение): имя и фамилия (совпадают у тысяч), должность (меняется),
локация (VPN или намеренно ложная), геолокация IP, WHOIS-контакты, имя-матчинг между базами.

### Каскад идентификаторов

Цель — превратить один известный факт в полный профиль:

```
Email   → Gravatar → фото → обратный поиск (Google Lens) → соцсети
        → [BreachData → другие аккаунты с тем же email]   ← вне рамок хранилища
Ник     → Sherlock / Maigret → список платформ
             ├─ GitHub → реальное имя + локация + репозитории
             ├─ Reddit → посты и интересы
             └─ Steam  → игровой профиль + страна
Телефон → WhatsApp → имя + фото + «был недавно»
        → Telegram → username + публичные группы
```

> Ветка по утечкам — пробив (см. [[Пробив и дата-брокеры]]). Каскад от телефона частного лица
> через мессенджеры — только в рамках авторизации; для учёбы — на своих данных.

**Правило 2+:** для однозначной идентификации нужно минимум **2 независимых надёжных якоря**.
(В хранилище это стыкуется с «правилом трёх» и грейдами A/B/C/D навыка `osint-research`.)

## Collision detection — защита от ошибок атрибуции

Самая опасная ошибка OSINT — **приписать факты одного человека его однофамильцу.**

Чеклист при совпадении имён:
- [ ] Совпадает компания / сфера деятельности?
- [ ] Совпадает география?
- [ ] Совпадает примерный возраст / фото?
- [ ] Есть ≥2 независимых факта, привязывающих к конкретному лицу?
- [ ] Проверена альтернативная гипотеза («это ДРУГОЙ человек»)?

При сомнении — **две отдельные сущности** (`ent_ivan_petrenko_techUA` и `ent_ivan_petrenko_kherson`).
Лучше две сущности, которые потом окажутся одной, чем одна склеенная, которая на самом деле две:
слить можно позже, а «разлить» без потери контекста — нельзя.

В инструментах: вместо слияния — ребро `POSSIBLY_SAME_AS` + свойство `verified: false`;
при противоречии полей (год рождения 1971 vs 1985) — статус `conflicted` и список противоречий с id источников.

## Пайплайн: от данных к графу

```
Сбор (веб, PDF, соцсети, БД)
 → Entity Extraction (NER, regex, LLM)
 → Нормализация («Іван» = «Ivan», «+380…» = «38…», даты в ISO 8601)
 → Deduplication (fuzzy match, vector similarity — слияние дублей)
 → Linking (установление связей)
 → Граф (Neo4j / Cytoscape) — анализ и визуализация
```

## Оценка уверенности в графе

Каждый узел и каждое ребро — с оценкой **1–10** и списком источников:

| Балл | Основание |
|---|---|
| 9–10 | детерминистическое совпадение (тот же ЕДРПОУ, email, телефон) |
| 7–8 | 2+ независимых источника |
| 5–6 | 1 надёжный источник |
| 3–4 | умозаключение / косвенные признаки |
| 1–2 | спекуляция — **не включать в отчёт** |

Пример: ребро «TechUA → связана → CryptoInvest UA» = 6/10 (общий IP + общий аналитик в LinkedIn) —
косвенная связь, требует подтверждения.

## Инструменты

| | Flowsint | Neo4j + OpenSanctions | OSINT Copilot |
|---|---|---|---|
| Тип | графовая OSINT-платформа | графовая БД + открытые данные о санкциях | десктоп-приложение с AI-агентом |
| Фокус | техразведка (домены, IP, email) | санкции, PEP, офшоры (ICIJ) | анализ источников, извлечение сущностей, отчёты |
| AI | энричеры + AI-чат | нет; готовые Cypher-шаблоны | Claude Code / Codex CLI / Hermes |
| Данные | PostgreSQL + Neo4j | FollowTheMoney → Cypher-скрипт | Markdown + YAML (FtM, STIX 2) |
| Лицензия | Apache 2.0 | код MIT, данные CC-BY-NC | подписка, есть пробный период |
| Установка | Docker + Make | Neo4j 4.4 + APOC + `load.cypher` | GitHub Releases + ключ |

Приватность: граф и заметки хранятся локально, но **AI-запросы Copilot уходят провайдеру модели** (Anthropic / OpenAI).

### Flowsint

- Open-source (`reconurge/flowsint`): React-фронт → FastAPI → core (Celery-оркестратор, Auth, Vault) →
  45+ энричеров → PostgreSQL (метаданные) + Neo4j (граф).
- Запуск: `git clone` → `cp .env.example .env` с **собственными** секретами (`AUTH_SECRET`,
  `MASTER_VAULT_KEY_V1`, `NEO4J_PASSWORD`) → `make prod` → `localhost:5173`. API-ключи — в Vault.
- 31 тип сущностей: сеть/инфраструктура (Domain, IP, ASN, CIDR, DNS Record, SSL Certificate, Web Tracker…),
  лица и контакты (Individual, Organization, Username, Email, Phone, Location…), финансы/крипто,
  безопасность/файлы.
- **Энричеры домена:** `domain_to_ip`, `ip_to_domain` (соседи по IP), `domain_to_subdomains` (crt.sh),
  `domain_to_whois`, `domain_to_history`*, `domain_to_asn`*, `domain_to_website` (* — нужен ключ).
  Без ключей работают DNS, WHOIS, поддомены, сайт, TLS.
- **IP-цепочка:** IP info (гео, ISP, тип: хостинг / residential / Tor exit, репутация) → ASN (кто реально
  контролирует) → CIDR (все диапазоны AS) → Organization → все её AS.
- **Ник → Maigret** (3000+ сайтов) → узлы Social Profile, ребро `same_nickname`.
- **Website:** краулер страниц, внешние ссылки (партнёры?), **web-трекеры (Google Analytics ID, Facebook Pixel)**,
  текст для AI-анализа. Тактика: два сайта с одним GA ID → вероятно один владелец (проверка: BuiltWith, SpyOnWeb).
- **Крипто:** wallet enricher (баланс, транзакции, контрагенты); NFT в кошельке может вывести на Discord/Twitter.
- **n8n-интеграция:** триггер (напр. алерт о новом домене) → `create_entity` → автозапуск энричеров →
  уведомление. Сценарии: ежедневный мониторинг доменов по шаблону, batch-обогащение, alert-пайплайн
  на бренд-имперсонацию.

> [!warning] Вне рамок хранилища
> В Flowsint и в примерах лекции есть энричеры **Email/Phone → Breaches** (HIBP, Dehashed) и типы
> Leak / Credential / Credit Card. Поиск чужих данных по утечкам — это пробив, вне discover-only
> (см. [[Пробив и дата-брокеры]]). Допустимо: HIBP только для самопроверки своего адреса.

**Кейс «подозрительный домен» (~20–30 мин вместо дней):** DNS → Hetzner; WHOIS — зарегистрирован 14 дней назад,
privacy guard; поддомены `login.`, `admin.`; история — 2 месяца назад парковка; на IP 47 доменов, 3 похожих
«invest»; сайт — login/dashboard/withdraw; общий GA ID → ещё 12 «invest»-сайтов → кластер из 15 сайтов,
одна инфраструктура, возможно один актор.

**Три ловушки реального прогона:** IP Cloudflare — геолокация «Торонто» = узел CDN, не сервер и не владелец;
WHOIS «withheld for privacy» — владелец скрыт; `abuse@<регистратор>` — почта регистратора,
**не привязывать к лицу**. Всё это слабые якоря.

### Neo4j + OpenSanctions

- OpenSanctions сводит санкционные списки разных стран в одну структурированную базу, обогащает данными
  о бенефициарах (OpenOwnership); формат **FollowTheMoney (FtM)**: Person, Company, Ownership, Sanction.
  После вторжения РФ темп вырос с ~7 новых лиц в неделю до ~300 в день.
- **offshore-graph:** OpenSanctions + ICIJ OffshoreLeaks в одном графе. Метки: `SanctionedEntity`,
  `Politician`, `Offshore`, `Address`. **Слияние по имени — слабый якорь**, проверять по правилу 2+.
- Установка: Neo4j 4.4 + APOC, ~8 ГБ heap; в `neo4j.conf` разрешить массовый импорт; выполнить
  `load.cypher` с `data.opensanctions.org/contrib/offshore-graph/exports/`.
- **OpenScreening** — веб-интерфейс к сети санкционных лиц без технических навыков.

```cypher
// санкционное лицо → офшор (до 5 шагов), не проходя через другие офшоры/адреса
MATCH p = (s:SanctionedEntity)-[*..5]-(t:Offshore)
  WHERE NONE(x IN nodes(p)[1..-1] WHERE (x:Offshore OR x:Address))
WITH p LIMIT 10
RETURN p;
```

Шаблоны из репозитория: политик → офшор (кратчайшие пути ≤5); санкционное лицо → компании по `OWNERSHIP`;
политик → платежи (`PAYMENT`) в радиусе 4; «Alert»: санкционные лица с `nationality: "ru"` → офшоры,
исключая пути через партии/госорганы, сортировка по длине пути (короче = сильнее).

### OSINT Copilot

- Десктоп (Windows/Linux, v0.14.7, osint-copilot.com), **local-first**: дело = папка на диске; сущности, связи,
  источники и чаты — Markdown + YAML (читаются без приложения; есть плагин для Obsidian).
- AI-агент (Claude Code / Codex CLI / Hermes) ставится отдельно; **изменения графа агент только предлагает**,
  применяются после подтверждения аналитика (Apply Selected Changes).
- Схемы: FtM, STIX 2, MITRE ATT&CK. Виды: чат, граф (несколько графов под гипотезы с общими сущностями),
  **таймлайн** (недатированное — отдельным блоком UNDATED, чтобы слух не выдавался за факт), карта
  (геолокация IP — слабый якорь), **доска (canvas)** для гипотез, доказательств и «открытых вопросов».
- **Skills** — Markdown-инструкции агенту (как проследить владельцев компании, проверить кошелёк или фейковый магазин);
  **task agents** — готовые задачи (напр. Case memo пишет меморандум дела).
- **HTTP-энричеры:** JSON-спецификация своего API; ключ — в папке credentials, **никогда в чате**;
  запросы выполняет приложение и **только к `allowedDomains`**; лимиты таймаута и размера ответа.

```json
{ "id": "crtsh-subdomains", "allowedDomains": ["crt.sh"], "auth": {"type": "none"},
  "request": {"method": "GET", "urlTemplate": "https://crt.sh/?q=%25.{{query}}&output=json"},
  "inputHints": ["domain"], "limits": {"timeoutMs": 20000, "maxResponseChars": 12000} }
```

- **Источники и доказательства:** каждая страница из браузерного расширения — заметка-источник (URL,
  выделение, заметки, время); evidence — архив MHTML, скриншоты и текст с **SHA-256**.
- **OPSEC:** поиск в Wayback выключен по умолчанию — запрос показывает Internet Archive, какие страницы вы изучаете.
- **`osint_confidence` считается по источникам, а не по уверенности модели:** 0 источников или только выводы
  агента → `unverified`; 1 → `low`; 2 → `medium`; 3+ → `high`. Независимые = разные URL (две копии одной
  страницы = один источник). Расхождение полей → `conflicted` + `osint_contradictions` (кто что говорит);
  **lock area** — проверенные узлы агент не может перезаписать.
- Конфликт источников (реестр Кипра: `cy`, слитый инвойс: `mt`) — приложение не выбирает само; решение за
  аналитиком через третий независимый источник.

## Интегрированный workflow

1. **Техразведка (Flowsint):** домен / email / IP → домены, IP, ники, кошельки → экспорт компаний, имён, email.
2. **Санкции и офшоры (Neo4j + OpenSanctions):** найденные лица и компании → Cypher-пути к
   `SanctionedEntity`, `Politician`, `Offshore`.
3. **Анализ и отчёт (OSINT Copilot):** экспорт + страницы через расширение → агент предлагает сущности и связи,
   уверенность по источникам → граф, таймлайн, карта, доска → меморандум дела.

## Этика и право

- **Запрещено:** доксинг; слежка за частными лицами без правовых оснований; несанкционированный доступ;
  использование данных для преследования/запугивания; продажа собранных данных третьим лицам.
- **Допустимо:** публичные лица (политики, чиновники) — в части публичной деятельности; антикоррупционная
  журналистика по публичным реестрам; CTI для защиты своей инфраструктуры; due diligence контрагентов.
- Flowsint ETHICS.md: использовать только в законных целях, не для преследования, доксинга и
  несанкционированной слежки.

## Главное для практики

1. Совпадение имени — не идентификация: нужно **≥2 независимых надёжных якоря** (email, телефон, кошелёк, хэш фото).
2. При сомнении — отдельные узлы + `POSSIBLY_SAME_AS` / `verified: false`; сливать только после проверки.
3. Всегда проверяй альтернативную гипотезу «это другой человек» по чеклисту collision detection.
4. Каждому узлу и ребру — балл 1–10 и список источников; 1–2 балла в отчёт не идут.
5. Уверенность — по числу **независимых** источников (разные URL), а не по уверенности LLM; противоречия фиксируй, не выбирай молча.
6. CDN-геолокация, privacy-WHOIS, abuse-почта регистратора — слабые якоря, к лицу не привязывать.
7. Общий GA/Pixel ID, общий IP, общие поддомены-шаблоны — сильные пивоты для кластеризации инфраструктуры.
8. Нормализуй перед дедупликацией: транслитерация, телефоны в E.164, даты в ISO 8601.
