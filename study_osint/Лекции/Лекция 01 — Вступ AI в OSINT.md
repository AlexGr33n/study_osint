# Лекция 01 — Вступ: AI в OSINT-исследованиях

## О чём лекция

Вводное занятие курса: что такое разведка (intelligence) и OSINT, и как генеративный AI (GenAI) работает
**мультипликатором силы** на каждом этапе OSINT-цикла, не заменяя аналитика. Обзор моделей (облако vs локально),
промпт-инжиниринга, сбора/обработки/анализа/распространения с помощью AI, угроз доверию (bias, недетерминированность,
дипфейки) и регуляторной рамки. Финал — ДЗ: развернуть локального агента и написать свой SKILL.

> [!info] Лектор
> Василь Попов — сооснователь OSINT FOR UKRAINE, CEO Probe Point Analytics, автор OpenDossier (AI due diligence
> отчёты), тренинги для Clooney Foundation, Amnesty International, EUROPOL.

## 1. Базовые понятия

- **Разведка (Intelligence)** — не «информация», а продукт дисциплинированного процесса: данные прошли
  **оценку, верификацию и контекстуализацию** и поддерживают принятие решений.
- **OSINT** (Open Source INTelligence) — разведка исключительно из публично доступных источников, без скрытого доступа.
  > [!warning] Рамка хранилища
  > В лекции в список «публичных источников» включены и **утечки баз данных**. В этом хранилище — discover-only:
  > утечки и пробив вне рамок, см. [[Пробив и дата-брокеры]].
- **Базовый цикл:** Сбор (сырые данные) → Обработка (структурирование, очистка) → Анализ (смысл, контекст) → Действие (передача разведпродукта).
- **Общая боль аналитика:** информационная перегрузка · языковой барьер · скорость vs качество.
  AI снимает рутину, а не аналитика: «слишком много данных, слишком мало времени, слишком много шума».

## 2. OSINT-цикл + GenAI (полный обзор)

| Этап | Что даёт AI | Инструменты из лекции |
|---|---|---|
| Планирование и постановка задач | Профилирование целей, формулировка требований; *в лекции также — sock puppets/легенды (см. §8)* | LLM |
| Сбор (Collection) | Оптимизированные поисковые запросы (булевы строки, Google dorks), генерация скраперов | LLM, BeautifulSoup, Playwright, Selenium |
| Обработка и эксплуатация | Перевод, транскрипция, детекция объектов, OCR зашумлённых документов | Whisper, YOLO, мультимодальные LLM |
| Анализ и сведение | Семантический поиск через эмбеддинги, структурированная интерпретация, «извлечение мудрости» | text-embedding-3, Sentence Transformers, ChromaDB, Weaviate, Fabric |
| Распространение (Dissemination) | Перефразирование под аудиторию, детекция предвзятости, QA отчёта | LLM, Fabric `create_report` |

Ключевой тезис: AI ускоряет каждый этап, но **ответственность за верификацию, суждение и этику — на аналитике**.

## 3. Выбор модели: облако или локально

| | Облако | Локально |
|---|---|---|
| Примеры | OpenAI (GPT-4.x, o1), Anthropic (Claude), Google Gemini | Ollama (CLI), LM Studio (GUI), Jan.ai (privacy-first) |
| Плюсы | Frontier-возможности, всегда обновлены | Полный контроль данных, возможен **air-gap**, нет оплаты за токен |
| Минусы | Данные покидают среду — риск для чувствительных расследований | Ограничены железом (VRAM), отстают от frontier |

**Четыре вопроса выбора:** безопасность данных? размер контекстного окна? мультимодальность? стоимость?

**Метрики лидербордов (для выбора под задачу):** интеллект/IQ (MMLU, HellaSwag, ARC) · кодинг (для скраперов) ·
контекстное окно · скорость (токены/с) и цена (за 1M токенов) · мультимодальность.
Фильтры: провайдер, только open-weight, поддержка дообучения (fine-tuning), параметры/контекст под железо.

- «Ни одна модель не лучше во всём» — выбирать под миссию, а не по бренду; **тестировать на своих OSINT-задачах**,
  бенчмарки не переносятся напрямую.
- Open-source догоняет проприетарные: Llama 3.x, Mistral/Mixtral (MoE), Qwen 2.5 (сильная мультиязычность, CJK),
  DeepSeek R1 (reasoning, можно локально). 8B-модели работают на игровых GPU.
- **Калькуляторы железа:** apxml.com/tools/vram-calculator (VRAM по размеру/квантизации),
  kolosal.ai/memory-calculator (облако vs локально), energy.inference.net (энергия на инференс).

> [!note] Снимок времени
> Сравнительные таблицы моделей в лекции (GPT-4.1, Claude 4 Sonnet, Gemini 2.5 Pro, DeepSeek R1, Llama 3.3 70B;
> «релизы октября–ноября 2025») — снимок на момент подготовки слайдов, быстро устаревает. Часть пунктов о релизах
> выглядит неточной (напр. «GPT-o1 Instant/Padding») — не опираться без проверки.

**Когнитивный vs генеративный AI:** когнитивный (правила, детерминизм, аудируемость — структурные запросы, извлечение
сущностей, булева логика) + генеративный (синтез, суммаризация, перевод, гипотезы). Сильнейшие процессы комбинируют:
когнитивный — для фильтрации, генеративный — для синтеза и коммуникации.

## 4. Промпт-инжиниринг: «Шесть столпов»

Промпт — главный интерфейс между аналитиком и моделью и самая важная навычка в AI-OSINT.
Структурированные промпты стабильно лучше неструктурированных.

1. **Роль (Role)** — кем является модель: «Вы — аналитик кибербезопасности, специализирующийся на атрибуции угроз…»
2. **Задача (Task)** — одна чёткая инструкция; **одна задача на промпт**.
3. **Контекст (Context)** — сырые данные, исходная информация, ограничения (вставлять документы/данные прямо в окно).
4. **Рассуждение (Reasoning)** — «думай шаг за шагом».
5. **Формат вывода (Output format)** — JSON / маркированный список / markdown-таблица.
6. **Условие остановки (Stop)** — когда завершить; снижает галлюцинации.

Шаблон:
```text
Роль: Ты — OSINT-аналитик, специализирующийся на <домен>.
Задача: <одно действие> по приведённым ниже материалам.
Контекст: <данные / документ / ограничения>. Используй только этот контекст.
Рассуждение: Действуй пошагово; разделяй факты и предположения.
Формат: <JSON со схемой … | markdown-таблица с колонками …>.
Стоп: Если данных недостаточно — напиши «недостаточно данных» и остановись; не додумывай.
```

## 5. Сбор данных: AI-поиск и скрапинг

- **Поисковые запросы:** просить LLM сгенерировать булевы строки, Google dorks и операторы под конкретную платформу.
- **Скраперы на заказ** (пример промпта из лекции, перевод):
  > «Напиши Python-скрипт для скрапинга всех постов с публичного форума по адресу [URL]. Извлеки автора, дату,
  > заголовок и текст поста. Автоматически обрабатывай пагинацию и сохраняй результаты в структурированный JSON.»
  Ожидаемый результат: BeautifulSoup/Playwright, обработка ошибок, **rate limiting**, схема JSON
  (`post_author, timestamp, post_id, content_text, thread_url`). Итерация — адаптация под новые сайты/поля.
- **Динамические сайты:** Playwright/Selenium для JS-SPA (подгрузка, бесконечная прокрутка).
- **Хранение:** SQLite (одиночное расследование) · Elasticsearch (полнотекст, большие корпуса) · ChromaDB/Weaviate (векторы для семантики).

> [!warning] Вне рамок хранилища
> Лекция упоминает обход антибот-защиты и CAPTCHA, работу через логин-флоу. В рамках хранилища — только публичные
> страницы, соблюдение ToS/robots.txt, вежливый rate limit; обход защит и авторизованных зон не практикуем.

## 6. Обработка: перевод, транскрипция, зрение, OCR

**Whisper (OpenAI)** — открытая многоязычная STT-модель (99 языков, акценты, шум, переключение языков), локально
через Python или API. Применение: пресс-конференции, видеобрифинги, подкасты; **транскрипты с таймкодами** для
реконструкции хронологии.

**Пайплайн «YouTube → разведпродукт»:** URL → транскрипция → LLM →
суммаризация · полный перевод · извлечение сущностей (люди, организации, локации, даты, **криптоадреса**) · хронология.

**Детекция объектов:** транспорт (марка, модель, цвет, зона номера), логотипы, оружие/техника, ориентиры и архитектура,
униформа/флаги. Инструменты: **YOLO** (open-source, локально), Google Vision API, AWS Rekognition, Roboflow (свои модели).
Демо: фото → детекция → **перекрёстная проверка** (публичные базы ТС, обратный поиск TinEye/Yandex) →
геолокация с **Overpass Turbo** / Google Maps.

**Мультимодальный промпт к изображению** (перевод из лекции):
```text
Опиши это изображение максимально подробно. Определи весь видимый текст, объекты, логотипы, лица,
географические признаки, погодные условия и любые другие детали, которые помогут установить место,
время или контекст этого изображения.
```
Плюсы мультимодальных LLM: встроенный OCR (вывески, чеки, номера), **контекстная интерпретация** (это телефон;
вывеска на японском; логотип организации), вывод сразу в JSON/таблицу для отчёта.
AI-OCR справляется с мятыми чеками, скриншотами мессенджеров (сохраняет макет), рукописными заметками.

> [!tip] Дисциплина
> Выход детектора/LLM по изображению — **гипотеза**, а не факт: «лица» и «геопризнаки» проверять независимо
> (правило трёх). Распознавание лиц частных лиц — вне рамок хранилища.

## 7. Анализ: Fabric, семантический поиск, кейс ransomware

**Fabric** (Daniel Miessler) — открытый фреймворк «паттернов» (готовых промптов) для любого контента.
```bash
fabric -y 'https://youtu.be/...' --stream extract_wisdom
```
| Паттерн | Назначение |
|---|---|
| `extract_wisdom` | Ключевые идеи, факты/статистика, цитаты с атрибуцией, рекомендации, ссылки, резюме в 1 предложении |
| `summarize` | Резюме для руководства (список / абзацы / markdown) |
| `analyze_claims` | Оценка утверждений: логика, доказательная поддержка, предвзятость, ошибки рассуждения |
| `create_report` | Форматированный разведотчёт из сырого анализа |

Паттерны можно соединять в цепочки (pipeline).

**Кросс-языковой семантический поиск:** текст → векторы смысла; фраза на украинском и её перевод на японский
ложатся рядом в векторном пространстве → запрос на одном языке находит контент на другом.
Инструменты: OpenAI text-embedding-3, Sentence Transformers (локально), ChromaDB, Weaviate (гибридный поиск).

**Кейс: переговоры с вымогателями (ransomware).** Транскрипты переговоров, нормализованные в JSON, — ценный
threat-intel источник. Последовательные промпты (перевод/обобщение из лекции):
- «Суммируй тон переговоров и хронологию.» / «Определи все даты, дедлайны и ультиматумы.»
- «Какие TTP прослеживаются в этом разговоре?» / «Соответствует ли стиль известным профилям ransomware-групп?»
- «Какие адреса криптокошельков упоминаются или подразумеваются? Перечисли с контекстом.»
- «Психологический профиль по языку и поведению: терпеливость, склонность к риску, операционная зрелость.»
- «Итог: был ли платёж, финальная сумма, предоставлено ли расшифрование? Отметь признаки недобросовестности.»

Приём: **сначала первичное извлечение, затем углубляющие follow-up промпты** под конкретные разведтребования.

## 8. Распространение: перефразирование, bias, QA отчёта

- **Детекция предвзятости:** «Определи любые предвзятости, нагруженную лексику, отсутствующие перспективы или
  политический крен в этой статье.» → идеологический фрейминг, перекос в выборе источников, логические несоответствия.
- **Перефразирование под аудиторию:** executive summary (кратко, стратегические последствия) vs технический отчёт
  (IOC, методология, инструменты).
- **AI как финальный QA-слой:** неподкреплённые утверждения, непоследовательная терминология, **излишне уверенный
  язык без доказательств**, логические пробелы.
- **Оценка достоверности источника:** история публикаций, сигналы экспертизы автора, согласие с известными фактами.

## 9. Доверие к AI: bias, манипуляции, недетерминированность

- **Bias — структурный:** модель наследует статистику корпуса; «мусор на входе — мусор на выходе, но в масштабе».
  Посты влиятельных людей (вкл. ложные утверждения) попадают в обучающие данные.
- Кейс **Grok**: критикуют одновременно за «слишком мягок к ложным утверждениям» и «слишком доверяет традиционным
  медиа» → **ни одна модель не нейтральный арбитр истины**.
- Проблема «хорошего бота»: ChatGPT, оценивая AI-контент в соцсетях, ответил «хороший бот» — модели поддаются
  **социальной инженерии через контекст промпта**; отравление контекста соцсетей — реальный вектор атаки на AI-OSINT.
- **Недетерминированность (MoE):** один и тот же запрос даёт разные сущности/выводы даже при temperature=0 —
  это свойство архитектуры. Рецензент может не воспроизвести результат.
  Митигация: фиксировать запросы и ответы **дословно**; несколько прогонов и сравнение; детерминированная
  постобработка (структурированное извлечение).
- **Документировать методологию:** модель, версия, промпт, шаги верификации — ради воспроизводимости и аудита.

## 10. Синтетические личности, морфинг, дипфейки — концептуально и для распознавания

> [!danger] Вне рамок хранилища
> Лекция рассматривает создание sock puppet-персон (вкл. генерацию фото и «досье легенды»), морфинг лиц и пайплайн
> создания дипфейков как наступательные приёмы скрытых операций. В хранилище фиксируем **только концепцию и
> распознавание/защиту**. Применение — лишь в авторизованных контекстах вне рамок этого хранилища; пошаговые
> инструкции сюда не переносятся. (Слайды 37 и 39 — иллюстрации без текста, не просмотрены.)

**Концепции:**
- **Sock puppet** — сфабрикованная онлайн-идентичность для скрытого сбора. GenAI резко удешевляет правдоподобные
  персоны (биография, стиль письма, синтетическое фото лица от GAN/diffusion) → в соцсетях стоит ожидать больше
  «идеальных» фейковых аккаунтов.
- **Морфинг лиц** — смешение двух лиц в синтетическое, наследующее черты обоих; цель — пройти беглую проверку и
  обойти обратный поиск изображений (публично демонстрировали Matt Edmondson, Nico Dekens).
- **Дипфейки** — GAN/diffusion замена лиц в видео (известные фреймворки: DeepFaceLab, Roop, SimSwap, faceswap);
  **клонирование голоса** по нескольким секундам образца (ElevenLabs, Vall-E, Tortoise TTS). Совмещение видео+аудио
  делает фейк многократно убедительнее.

**Как распознавать фейковый аккаунт/персону (вывод для защиты):**
- Фото профиля: обратный поиск; признаки синтетики (артефакты фона, ушей, аксессуаров, асимметрия); морфы могут
  не находиться обратным поиском — отсутствие совпадений ≠ подлинность.
- Несоответствие «легенды» и цифрового следа: молодой аккаунт, нет истории, слишком гладкая и согласованная биография.

**Чеклист детекции видео-дипфейка:**
- [ ] Граница наложения: размытие у челюсти и линии волос
- [ ] Моргание: неестественная частота/паттерн (ранние GAN почти не моргали)
- [ ] Кожа: текстура (поры, морщины) не совпадает с телом; цвет лица ≠ шея/уши
- [ ] Деформация фоновых объектов у периферии лица
- [ ] **Глаза** (самый надёжный индикатор исторически): разные блики/отражения в левом и правом глазу, текстура и
      цвет радужки, отсутствие бликов, асимметричное моргание, взгляд не следует за движением головы
- [ ] **Микровыражения**: плоский аффект при эмоциональных заявлениях, асимметрия, несвойственная базовому поведению,
      рассинхрон речи и мимики
- [ ] Аудио отдельно: спектральные аномалии, неестественная просодия, сравнение с аутентичными образцами речи

Diffusion-дипфейки 2024–2025 проходят поверхностную человеческую проверку → нужны автоматические инструменты
**вместе** с ручным осмотром.

**Инструменты детекции:** Intel FakeCatcher (кровоток), Deepware Scanner, Microsoft Video Authenticator (покадровая
оценка), **InVID / WeVerify** (браузерный плагин: ключевые кадры, обратный поиск по кадрам, метаданные, базы фактчекинга —
основной инструмент практиков).

**Методология проверки видео публичного лица (4 уровня):**
1. **Компрессионные артефакты** — следы повторного кодирования (у дипфейков необычные схемы после нескольких этапов обработки).
2. **Провенанс** — самая ранняя загрузка и цепочка распространения.
3. **Метаданные** — EXIF, GPS, временные метки.
4. **AI-детекция** — FakeCatcher, Deepware, InVID; **никогда не полагаться на один инструмент**.

Ни одного шага недостаточно: сверять все четыре, документировать каждый для независимого воспроизведения.
Принцип: **в эпоху дипфейков видео не самодостаточно аутентично** — значимое видео проходит криминалистическую проверку
до включения в отчёт.

## 11. Этика и право

## Главное для практики

1. AI — **аналитик первого черновика**, не финальный арбитр: каждое существенное утверждение модели проверять по
   независимым первоисточникам.
2. Промпт по «Шести столпам»: роль → одна задача → контекст → пошагово → формат (JSON/таблица) → условие остановки.
3. Чувствительное расследование — **локальная модель** (Ollama / LM Studio); облако — только для нечувствительных данных.
4. Журнал AI-методологии в каждом деле: модель + версия + дословный промпт + ответ + шаги верификации; при важных
   выводах — несколько прогонов и сравнение.
5. Сначала структурированное извлечение (сущности, даты, криптоадреса, хронология), затем углубляющие follow-up промпты.
6. Видео/аудио не аутентичны по умолчанию: провенанс → метаданные → компрессия → ≥2 инструмента детекции + ручной осмотр (глаза, микровыражения).
7. Контент из соцсетей в промпте — потенциальная атака (отравление контекста / prompt injection): помечать как данные, не инструкции.
8. Перед отправкой отчёта — AI-QA: неподкреплённые утверждения, излишняя уверенность, пробелы логики, предвзятость источников.
