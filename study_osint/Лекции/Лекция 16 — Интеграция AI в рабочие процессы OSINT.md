## О чём лекция

Как превратить собранное в **аналитический продукт** для решения и где тут полезен AI: стандарты отчёта (BLUF, уверенность, источники), промптинг (R.O.C.E., ACH), Obsidian + Dataview, отчёт на Python (pandas → Plotly → Jinja2), карты (QGIS, Kepler.gl), агенты Claude Code (ReAct). AI берёт механику, **подпись и ответственность — за человеком**.

Занятие — 120 минут, перерыв после первого демо; пять частей (отчёт → промптинг → Obsidian → Python и карты → агенты) и три демо в Claude Code. Девиз со слайда: AI забирает всё, что не требует думать, чтобы аналитик думал больше.

## Что отдавать AI

По слайду (без ссылки на исследование) время аналитика: сбор данных 35%, написание отчёта 25%, перевод и нормализация 18%, поиск по заметкам 10%, **собственно анализ 12%**.

- **AI — можно**: перевод и нейтральный стиль, черновик и executive summary, код для парсинга и графиков, альтернативные объяснения, поиск пробелов, поиск по заметкам (RAG).
- **Только аналитик**: надёжность источника, атрибуция, суждения с юридическими/оперативными последствиями, суждения в условиях неопределённости, подпись.

Цикл: факты (аналитик) → черновик (AI) → суждения и атрибуция (аналитик) → стиль (AI) → проверка и подпись (аналитик).

## Разведывательный отчёт

**До письма — три вопроса.** (1) Цель → тип продукта: предупредить — *flash*, проверить гипотезу — *assessment*, база для решения — *strategic estimate*, для суда — *forensic report*. (2) Аудитория: технарю — методология и метрики; руководителю — выводы, риски, действия; юристу — цепочка доказательств и нейтральный язык; СМИ — без жаргона, с визуализацией. (3) Какое решение примут по отчёту — неясно, значит уточнить у заказчика **до начала работы**. Промпт со слайда: «Я пишу OSINT-отчёт для [аудитория] с целью [цель]. Какая структура подходит лучше всего?»

| Тип | Объём | Назначение |
|---|---|---|
| Flash report | 1 абзац | Срочное предупреждение (~2 часа) |
| Spot report | 1 страница | Одно событие или находка |
| Assessment | 2–5 стр. | Углублённый разбор |
| Strategic estimate | 10–20+ стр. | Долгосрочный прогноз |

**Семь секций:** титул (организация, дата, гриф, номер кейса) · **BLUF** · введение (цели, scope, вопросы) · методология · находки (**факты отдельно от оценок**) · анализ (key judgements с уверенностью, альтернативы, пробелы) · выводы и рекомендации (конкретные, приоритизированные).

### BLUF (Bottom Line Up Front)

Главный вывод — первой фразой: `вывод + уровень уверенности + главный факт`, а не объём данных с осторожным «допускаем координацию» в конце. Не можешь написать BLUF — анализ не закончен. LLM можно поручить переписать первый абзац в этот формат.

### Уверенность и вероятность

Нет явного уровня уверенности — **ошибка**, а не нейтральность.

Уровни: **высокая** («с высокой уверенностью оцениваем» — несколько независимых источников, картина непротиворечива) · **умеренная** («оцениваем», «вероятно» — есть пробелы или альтернативы) · **низкая** («допускаем» — один источник, мало данных).

Шкала слов: почти наверняка > 95% · весьма вероятно 75–95% · вероятно 55–75% · равные шансы 45–55% · маловероятно 25–45% · очень маловероятно 5–25% · почти исключено < 5%. Границы чуть отличаются от ICD 203 (там «likely» 55–80%) — главное держать одну шкалу на весь отчёт. LLM полезен как проверяющий: разметить все суждения уровнем уверенности.

### Методология и источники

Методология (инструменты, источники и период, верификация, ограничения) даёт воспроизводимость, юридическую защиту (цепочку доказательств) и делает видимыми пробелы.

- **Три независимых источника** для ключевого факта — не ссылаются друг на друга, разного типа: первичный + вторичный + верифицирующий. Несколько записей **одного агрегатора** — это один источник, а не подтверждение (акцент демо 1).
- **Надёжность**: проверенный первичный — высокая; вторичный или неподтверждённая идентичность — умеренная/низкая; неподтверждённое от неподтверждённого — не использовать.
- **Цитирование**: дата доступа, архивная копия, ссылка на конкретную страницу. **Текст LLM — не источник.**

## Промптинг для аналитика

Промпт = **техническое задание**: роль · контекст · задача · формат ответа · ограничения («данных мало — скажи прямо») · входные данные. Без ограничений модель додумывает «удобное».

**R.O.C.E.** — Role · Objective · Context (что известно) · Evidence (сами данные, чтобы не выдумывала). Пример урока (язык, часовой пояс, связь аккаунта со старым ником) — в хранилище только для публичных аккаунтов и кампаний влияния, не для установления личности частного человека.

Шаблоны задач: **синтез источников** — консенсус, противоречия, уникальное с оценкой надёжности, хронология, без своих оценок · **манипуляции нарративом** — опущенные факты, эмоциональная окраска, повторяющийся фрейминг, синхронность, к пункту цитата и уверенность · **хронология** — `дата | событие | источник | статус`, разрывы выделить · **gap analysis** — неотвеченные вопросы и какой источник их закроет.

Приём **«Why?»** (слайд): после каждого вывода ещё раз спросить «почему?» — так вскрывается, на чём вывод держится.

### ACH — анализ конкурирующих гипотез

Метод Ричардса Хойера (ЦРУ) против confirmation bias: гипотезы **отбрасывают противоречиями**, а не подтверждают совпадениями.

| Доказательство | H1 координация | H2 органика | H3 накрутка |
|---|---|---|---|
| Синхронность ±5 мин | ++ | −− | + |
| Пересечение участников 78–91% | ++ | − | ++ |
| Дословно одинаковый текст | ++ | −− | − |
| Монетизации нет | + | ++ | −− |

Меньше всего противоречий у H1. Промпт: 3–5 гипотез, оценки `++ / + / ? / − / −−` по списку доказательств, таблица Markdown, гипотеза с минимумом противоречий. Матрицу от LLM **вычитывает человек**. (В уроке есть строка «разные IP авторов» — в открытых источниках таких данных обычно нет.)

## Obsidian как база расследования

Локальные `.md` без облака: git для версий, `[[ссылки]]` строят граф, frontmatter — поля для Dataview, Canvas — локальная замена Maltego. Плагины: Dataview, Templater, QuickAdd. Папки: `00-Дашборд`, `01-Субъекты`, `02-События`, `03-Доказательства`, `04-Источники`, `05-Отчёты`.

Шаблоны: **субъект** (тип, имя, псевдонимы, статус `подтверждено / вероятно / отброшено`, уверенность, связанные организации и источники как wikilinks; в теле — факты, связи, пробелы) и **событие** (дата, время, место, участники, доказательства, статус).

```dataview
TABLE name, confidence, updated
FROM "01-Субъекты"
WHERE status = "вероятно"
SORT updated DESC
```

Ещё: таймлайн событий (`SORT date ASC`), субъекты без связей (`WHERE !related`) как список пробелов, `dataviewjs`-сводка счётчиков.

> Ключи в уроке кириллические с апострофами — надёжнее латинские. В слайдах это уже оговорено: поля без апострофов, иначе Dataview их не прочитает; `{{date}}` и `{{title}}` подставляет встроенный плагин Templates, Templater добавляет логику (`<% tp.date.now() %>`). Шаблон «особа» с e-mail человека — досье на частных лиц тут **не ведём**; шаблоны — для организаций, публичных аккаунтов, кампаний.

## Python: отчёт из данных

`CSV/JSON → pandas (агрегаты) → Plotly (графики) → Jinja2 (Markdown/HTML) → weasyprint/pandoc (PDF)`

```python
daily = df.groupby("date").agg(messages=("message_id", "count")).reset_index()
stats = {"total": len(df), "peak_day": str(daily.loc[daily.messages.idxmax(), "date"])}
report = env.get_template("report_template.md").render(**stats)
```

Шаблон Jinja2 — spot report с переменными (`{{ peak_count }}`) и условиями (`{% if %}` для предупреждения об аномалии). Графики Plotly (HTML): **heatmap «день × час»** — часовой пояс оператора; **betweenness vs PageRank** — роли узлов; **bar race по неделям** — смена лидеров.

**В слайдах** пример другой — шаблон демо 3 по санкционным записям объекта: заголовок `SPOT REPORT — {{ object }}`, статус «авточерновик, не подписан»; BLUF из цифр (`records_unique` записей в `jurisdictions` юрисдикциях, последняя — `last_date`); `{{ img("timeline") }}`; блок-предупреждение `{% if recent_count > 0 %}` о новых записях за 36 месяцев; пробелы от LLM циклом `{% for gap in llm_gaps %}` как чекбоксы `- [ ]`. Полный скрипт `make_report.py` (~250 строк) в материалах урока. Три графика из него: heatmap **час × день недели** (синхронные публикации → рабочий график оператора: будни, 09–18), матрица **«кто с кем»** (сколько раз пара каналов дала одинаковый текст — кластер виден сплошным блоком), столбцы **по годам и юрисдикциям** (волны 2015 и 2022, записи без даты отдельно). Темы light/dark, PNG для отчёта, HTML для интерактива; scatter betweenness × PageRank и bar race ушли в материалы.

**AI пишет скрипт**: в промпте — колонки с типами, шаги, формат вывода, библиотеки. Перед запуском проверить кодировку, пути, пустые значения, размер выборки (матрица близости может не влезть в память); ошибку вернуть модели с первыми строками данных — обычно 2–4 итерации.

> Мелочи кода урока: `{{ now }}` не передаётся в `render()`; PNG через `write_image` требует `kaleido`; «топ-10» в bar race не ограничен.

## Карты в отчёте

Карта — **доказательство**, не иллюстрация: нужна, если место — часть находки (геолокация, маршрут, «заявлено vs на самом деле»); не нужна при точности хуже ~30 км или если дублирует таблицу. Обязательно: масштаб, север, легенда, источник и дата подложки, сетка/bbox, CRS. LLM может описать паттерн словами — без оценок.

**QGIS**: CSV с `lat`/`lon` в десятичных градусах → слой → подложка (QuickMapServices) → Heatmap/Buffer/Join при необходимости → стиль → **Print Layout** со всеми обязательными элементами → PNG 300 dpi или PDF. Плагины: QuickOSM, Streetview.

Подготовка CSV в pandas (слайд): оставить `lat, lon, event_type, date, source`, `dropna(subset=["lat", "lon"])`, сохранить в UTF-8; координаты — `50.4501`, а не `50°27'N`. В Print Layout: Add Item → Map, Scale Bar, North Arrow, Legend, Label (источник, CRS, дата) → Export as Image. На занятии QGIS вживую не показывали — карту в демо 3 строит Plotly, но чек-лист годится для любого инструмента. Kepler.gl из Python: `KeplerGl(height=600)` → `add_data(df_map, name="events")` → `save_to_html("report_map.html")`.

Выбор: анализ (buffer, join), печать, чувствительный кейс → **QGIS** локально · миллионы точек и HTML → **Kepler.gl** (есть Python-обёртка) · сверка с историческими снимками → **Google Earth Pro** · совместная работа → **Felt** (облако — не для чувствительного) · публичная карта self-hosted → **uMap** · хороплет для публикации → **Datawrapper**.

## Агентные воркфлоу

Агент сам разбивает цель на шаги, вызывает инструменты и правит план. **ReAct**: `THINK → ACT → OBSERVE` до цели, каждый шаг — в трейсе. Инструменты Claude Code: WebSearch, Bash (whois, curl, Python), Read/Write, MCP — на слайде **MCP Gephi** (сетевой анализ), **MCP Neo4j** (запросы к базе), **MCP n8n** (воркфлоу сбора из урока 10). Плюс: описываешь цель, а трейс документирует методику.

Пример — бриф по домену: WHOIS → DNS (A, MX, TXT, NS) → упоминания в открытых источниках → TLS-сертификат → BLUF + факты + уровень угрозы, «данных нет» — явно. Это пассивные проверки ([[Пивоты по идентификатору]]); `dig ANY` многие серверы не обслуживают (RFC 8482) — запрашивать типы по отдельности. В трейсе слайда полезный шаг — **пассивный DNS**: IP домена хостит ещё два «медийных» домена, это пивот по инфраструктуре.

> В демо ReAct есть шаг проверки e-mail регистранта по утечкам (HIBP; на слайде — «найден в 2 утечках»), а в примере агента — `web_search("… pastebin")` в поисках утечек. Оба шага **вне рамок хранилища**, см. [[Пробив и дата-брокеры]].

**Сквозной кейс** (дезинформация), тайминг со слайда — ~2 часа против 2–3 дней без AI, из них ручной работы аналитика ~45 минут:

| Этап | Время | Что делается |
|---|---|---|
| Сбор | 30 мин | Groupint → 47 Telegram-каналов → Neo4j; агент делает WHOIS всех доменов |
| Сеть | 20 мин | gephi-ai + Claude: modularity, betweenness, PageRank → PNG + GEXF |
| Контент | 25 мин | Скрипт от Claude: матрица косинусной близости → 11 каналов с идентичным текстом в окне ±3 мин |
| Синтез | 15 мин | R.O.C.E. → ACH из трёх гипотез → H1 (координированная операция) |
| Отчёт | 30 мин | Черновик Jinja2 → Claude правит стиль и уровни уверенности → аналитик: атрибуция, подпись, PDF |

На сайте подзаголовок говорит «4 часа», в BLUF-примере 10 каналов из 47, в кейсе 11 — цифры иллюстративные.

## Где AI ошибается

1. **Галлюцинации** цитат, дат, URL — в отчёт только проверенное; разрешить модели ответ «неизвестно».
2. **Предвзятость формулировки** — «докажи координацию» даст доводы «за»; спрашивать обе стороны, применять ACH.
3. **Гладкость ≠ доказательность.**
4. **Утечка данных** — PII субъектов не отправлять в коммерческие API; чувствительное — локально (Ollama + Gemma/Llama).
5. **Зависимость** — кто перестал проверять AI, перестал быть аналитиком.

Итог слайдов: база знаний — это шаблон плюс запрос (шаблон держит структуру, запрос показывает пробелы); один шаблон — сколько угодно отчётов.

- **Уровень 1**: spot report ≥ 400 слов на украинском по публичному кейсу (BLUF, 3–5 key judgements с уверенностью, пробелы, оценка источников, какой промпт и что правили) + Obsidian с Dataview и Templater: 2 субъекта, 1 событие, Dataview-таблица «вероятно», скриншот.
- **Уровень 2**: скрипт CSV → ≥ 2 агрегата → ≥ 2 графика → Markdown через Jinja2 (записать промпты и итерации); ACH ≥ 3 гипотез × 5 доказательств с разбором ошибок AI; карта ≥ 5 событий (`lat, lon, event_type, date, source`) по стандартам — в PDF это бонус +10, на новой странице просто пункт.
- **Уровень 3**: Claude Code агентом на OSINT-задачу, трейс, разбор ошибок агента, итоговый spot report со своей редакцией.

Формат сдачи и критерии со страницы ДЗ убраны; в PDF — «на платформе». **Прежняя версия (до 2026-11-10):** сдача — отчёт, скриншот, скрипт/output, трейс агента; защита 5–7 мин. Веса: структура отчёта 35/25/20% · качество анализа 30/25/25% · Obsidian/автоматизация 20/25/20% · рефлексия 15% · агент и трейс — 20% на уровне 3.

## Главное для практики

1. Цель, аудитория и решение — до текста; тип продукта следует из цели.
2. **BLUF** первой фразой, уровень уверенности у каждого суждения, одна шкала вероятностей.
3. Факты отдельно от оценок; ключевой факт — три независимых источника, дата доступа и архивная копия; текст LLM — не источник.
4. Промпт как ТЗ (R.O.C.E. + формат + право сказать «данных нет»).
5. Против предвзятости — ACH; матрицу от модели вычитывать.
6. Obsidian: латинские ключи, статус и уверенность как поля, Dataview-запросы «не подтверждено / без связей» как список пробелов.
7. Повторяемый отчёт — pandas → Plotly → Jinja2; шаблон считает цифры, но уровень уверенности оставляет пустым для аналитика; карта только с масштабом, севером, легендой, источником и датой подложки.
8. Агенту — цель, пассивные инструменты и границы, API-ключей он не видит; трейс хранить; PII — только в локальные модели; подпись — человеческая.
