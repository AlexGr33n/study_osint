# Лекция 10 — Автоматизация сбора: API, скрапинг, пайплайны и гигиена данных

> Название в PDF: «Автоматизація збору: API / скрапінг / пайплайни та гігієна даних». На титульном слайде стоит **«Заняття №9»**, хотя файл назван «Лекція 10»; по программе урок 10 — «Моніторинг реального часу та алерти». Мониторинг и сигналы здесь есть, но как финальный блок про сбор.

## О чём лекция

Как превратить ручной сбор в **воспроизводимый и аудируемый** пайплайн: три способа сбора (API, скрапинг, RSS) плюс управляемые платформы, четыре фазы пайплайна, канонический запись с атрибуцией, модель сущностей FollowTheMoney. Три демо в n8n (с параллелью на Python): медиа-мониторинг → Obsidian, скрапинг без API, обогащение объекта через OpenSanctions → отчёт. Финал — мониторинг по расписанию, этика/OPSEC и сравнение инструментов.

## Зачем автоматизировать

| Вручную | Автоматически, с гигиеной |
|---|---|
| 20 источников ≈ 2 часа | Тот же сбор ≈ 3 минуты и каждый раз одинаково |
| Каждый раз немного по-разному | Каждая запись несёт: откуда, когда, каким сборщиком, по какому запросу |
| Нет дат сбора и сырых копий — отчёт не воспроизвести | Сырой HTML/JSON лежит рядом с извлечением |
| Дубли из разных источников считаются «подтверждением» | Дубли убираются по стабильному id, а не «на глаз» |

Цель — **не скорость, а воспроизводимый и аудируемый сбор**. Анализ и суждение остаются за человеком.

## Три способа сбора + управляемые платформы

| Способ | Плюсы | Минусы | Примеры | n8n · Python |
|---|---|---|---|---|
| **API** | JSON по документации, стабильный формат | Ключ, регистрация, лимиты, иногда геоблок | OpenSanctions, Tavily, Shodan, Jina Reader; Telegram API (Telethon) | HTTP Request · `requests` |
| **Скрапинг** | Гибкий доступ к публичному HTML без API | Ломается при смене разметки; 403, CAPTCHA | `t.me/s/<канал>`, портал ГУР «Війна і санкції», сайты компаний | HTML Extract + Code · `BeautifulSoup` |
| **RSS / фиды** | Самое дешёвое: без ключей и парсинга | Только свежие записи, без истории | Укрінформ, УП, Суспільне; **RSSHub** как мост для Telegram | RSS Read · `feedparser` |

**Управляемые платформы** (ScrapingBee, Apify, Bright Data): браузер, прокси, снимки за кредиты. Условия сайта остаются **вашим** риском, а вендор **видит ваши цели**. Нужны не для обхода защит, а когда без браузера страница пустая или нужен снимок-доказательство. Кредиты ScrapingBee: 1 без JS · 5 с JS · 10–25 через прокси.

Рабочий паттерн — **гибрид**: реестры/API дают точные поля, новости и каналы — контекст; всё это отдельные ветки одного пайплайна.

## Анатомия пайплайна: четыре фазы

1. **Сбор** — RSS / HTTP+HTML / API; три формата на входе, Merge на выходе.
2. **Дедупликация** — канонический запись и стабильный id = хеш(platform + URL); удаление дублей внутри прогона и **между прогонами** (Python: `set`, таблица `seen` в SQLite).
3. **Обогащение** — LLM-узел (резюме, сущности) и API-обогатители: OpenSanctions, crt.sh, ip-api, Wayback. **Данные передаются в тегах, а не как инструкции** (защита от prompt injection).
4. **Хранение** — запись `.md` с frontmatter в Obsidian-vault рядом с сырым `.json`.

**Мониторинг** = тот же пайплайн + Schedule Trigger/cron + дедупликация между прогонами. История выполнений/логи = аудит-лог.
Каждая фаза — отдельный узел или функция: видно, что вошло и что вышло («проверять каждый шаг»).

## Гигиена данных: канонический запись

Пять принципов:
1. **Нормализация** — UTF-8, даты в ISO 8601 и UTC, единые ключи полей (телефоны, ФИО — в едином формате).
2. **Дедупликация по стабильному id**, а не по похожести заголовков (составной ключ, напр. `hash(username+platform)`).
3. **Атрибуция** — `source_url`, `collector`, `query`, `collected_at` в каждой записи.
4. **Версионирование** — сырой HTML/JSON хранится рядом с извлечением.
5. **Аудит-лог** — кто, когда, каким воркфлоу; логи не чистить.

Шаблон записи (сокращённо):

```yaml
id: 9f2c…e1            # хеш platform + url
platform: telegram | rss | web
collector: HTTP Request + HTML
source_url: https://t.me/<канал>/<id>
title: …
published_at: 2026-10-26T11:34:08Z
collected_at: 2026-10-26T18:02:10Z
query: медиа-мониторинг …
raw: raw/2026-10-26_telegram_9f2c….json
```

> Если отчёт нельзя воспроизвести по этим полям — это не сбор, а впечатление.

## FollowTheMoney (FtM) — язык сущностей

- Сущность = `{id, schema, properties}` — одна модель для людей, компаний, адресов и связей.
- Схемы: Person, Company, LegalEntity, Address, Sanction, Directorship, Ownership, Family.
- **Связь — тоже сущность**: Directorship имеет director, organization, role, startDate.
- Формат общий для Aleph (OCCRP), OpenSanctions, yente; утилита `ftm` экспортирует в **Neo4j и Gephi** → мост к [[Лекция 08 — Теория графов в OSINT]].
- Одна функция переводит нормализованный запись в FtM, ответ OpenSanctions уже приходит в FtM: одна модель → один граф.

## Источники-API для обогащения

| Категория | Источник | Условия |
|---|---|---|
| Санкции и PEP | **OpenSanctions** — OFAC, ЕС, Великобритания, СНБО, ГУР «Війна і санкції», RuPEP, список ФБК в одной точке | Ключ бесплатно для СМИ, НКО, академии, госорганов Украины; иначе ≈ 0,10 € за вызов; bulk-данные бесплатно (CC BY-NC); **yente** — свой сервер |
| Реестры компаний | **OpenCorporates** | Ключ по заявке с доказательством общественной пользы, ≈ 500 запросов/мес |
| | **North Data** | 27 стран (без РФ), API по договору от 6 мес, **скрапинг сайта запрещён** |
| | Украина: **ЕГР через data.gov.ua**; YouControl, Opendatabot | Последние два — платные API |
| Без ключа и регистрации | **crt.sh** (сертификаты → поддомены), **ip-api** (гео, ASN), **Wayback** (архив), **Wikidata** | Бесплатно |
| Утечки | LeakCheck, HIBP, BreachDirectory | В лекции **не показывались**; персональные данные — только по мандату и из изолированного контура. **Вне рамок хранилища** (discover-only, без пробива по утечкам) — см. [[Пробив и дата-брокеры]] |

### OpenSanctions: три метода API

| Метод | Что делает | Когда |
|---|---|---|
| `/search?q=…` | Быстрый поиск по строке; фильтры schema, countries, topics, datasets; кандидаты с caption, topics, датасетами | Первый шаг — найти id |
| `/entities/{id}?nested=true` | Полная FtM-сущность: алиасы, ИНН/ОГРН, адреса, сайт; санкции (орган, программа, дата); связи directorship / ownership / family / associates / succession; `first_seen`, `last_seen`, datasets | Досье и граф |
| `/match` | Структурное сопоставление: schema + name + birthDate + nationality → кандидаты со **score** и флагом match | Проверка «тот ли это» |

**Score — не вердикт**: 0.78 без даты рождения — кандидат на проверку, а не факт. Порог и правило решает аналитик.

## Демо (что показано)

**Демо 1 · медиа-мониторинг в n8n → Obsidian.** Настройки (путь к vault, RSS Укрінформу, публичный канал Суспільного, запрос Tavily) → три ветки (RSS Read · HTTP+HTML на `t.me/s` · Tavily API) → Merge → нормализация → дедупликация → лимит 10 → резюме LLM (Gemini) с правилом безопасности → запись в vault: `inbox/` + Dataview-таблица. Расписание 30 мин. Три Code-узла делают нормализацию, а не сбор; на Python это ~120 строк.

**Демо 2 · скрапинг без API.** Портал ГУР: API нет, robots.txt разрешает → HTTP Request с **честным User-Agent** + HTML Extract (12 компаний «Ростеха»). Карточка объекта через ScrapingBee: `extract_rules` → JSON без парсера, `screenshot` → снимок-доказательство в vault. Сайт объекта из-за рубежа отдаёт 503/404 — **не обходим**, берём архивную копию Wayback. ИНН/ОГРН с ГУР совпали с OpenSanctions — независимое подтверждение. **Отказ сайта — тоже данные**: фиксируем статус и дату.

**Демо 3 · обогащение объекта.** OpenSanctions search → entity с nested-связями; параллельно crt.sh, ip-api, Wayback, Tavily-новости → Merge → сборка досье в FtM → LLM → JSON с риском и пробелами → отчёт и заметки сущностей в vault → граф Obsidian. Один объект, пять источников, один Merge; 32 санкционные записи и связи — из одного вызова; связанные лица — отдельные заметки с wikilinks.

## Структура vault после прогона

```
OSINT-vault/
  inbox/        YYYY-MM-DD_<platform>_<id>.md
  raw/          YYYY-MM-DD_<platform>_<id>.json
  entities/     <Сущность>.md
  reports/      report_<объект>.md, sources_<объект>.md
  attachments/  снимки-доказательства .png
  Монитор.md    ← Dataview-таблица
```

```dataview
TABLE platform, source_name, published_at
FROM "inbox"
SORT published_at DESC
```

Frontmatter = колонки таблицы; wikilinks между сущностями = граф Obsidian; сырьё рядом — до источника в один клик. Obsidian — аналитический слой над файлами, которые пишет пайплайн.

## AI-анализ: формат ответа

LLM работает **только над собранным**, отвечает JSON и привязывает каждый red flag к полю досье. Пример (вымышленный):

```json
{
  "overall_risk": "Низкий",
  "status_changes": ["новых санкционных записей за год нет"],
  "red_flags": ["единоличное руководство без соучредителей"],
  "recommendation": "Продолжить взаимодействие с мониторингом",
  "next_steps": ["проверить финансовую отчётность за год"]
}
```

## Отчёт: обязательные разделы

1. **Объект** — название, домен, идентификаторы (ИНН, ОГРН, OpenSanctions id), дата сбора, воркфлоу/скрипт.
2. **Источники** — каждый с датой: first_seen/last_seen, published_at, timestamp Wayback, снимок.
3. **Сущности** — FtM-сущности и связи; лица — отдельные заметки с wikilinks на компанию и отчёт.
4. **AI-анализ** — JSON: риск, уверенность, red flags с полем-источником, рекомендация, следующие шаги.
5. **Пробелы** (обязательно) — что не удалось проверить и почему (crt.sh не ответил, реестр платный, сайт недоступен).

Правило: вывод воспроизводится другим человеком по вашим шагам; шаги — узлы/функции, файлы — доказательства.

## Типовые проблемы и решения

- **HTTP 429** — паузы, exponential backoff, дробить запросы; логировать для перепроверки.
- **403 / CAPTCHA** — официальный API или RSS, архивная копия, управляемая платформа с оглядкой на ToS и OPSEC; для Telegram — публичное превью `t.me/s` с паузами. CAPTCHA не обходим.
- **Неполные данные** — пайплайн не выдумывает, а пишет «не установлено» (continue on error + раздел «пробелы»).
- **Некорректный ввод** — валидация названия, домена, ИНН/ОГРН до первого запроса.
- **Независимое подтверждение** критичных полей (адрес, ИНН совпадают в реестре и на сайте).
- Выход — структурированный JSON/CSV с едиными ключами; сырые ответы сохранять.

### Словарь n8n ↔ Python

| n8n | Python |
|---|---|
| HTTP Request | `requests.get(url, headers=UA, timeout=30)` |
| HTML Extract | `BeautifulSoup(html).select('.card')` |
| RSS Read | `feedparser.parse(url).entries` |
| Code | функция `normalize(record)` |
| LLM-узел | SDK модели: system + user, ответ JSON |
| Convert + Write File | `Path(vault, 'inbox', name).write_text(md)` |
| Merge | `list.extend` / `asyncio.gather` |
| Remove Duplicates | `set(id)` в прогоне; таблица `seen` в SQLite между прогонами |
| Retry on Fail | `tenacity`: `@retry(wait=wait_exponential(3, 48))` |
| Batching | `time.sleep(2)` между запросами; семафор для параллели |
| Schedule Trigger | cron, APScheduler, systemd timer |
| Executions | logging в файл + `raw/*.json` |

## Мониторинг по расписанию

- Запуск: cron / APScheduler / Schedule Trigger — каждые 30 мин, ежечасно.
- Память увиденных id между прогонами (таблица `seen` или Remove Duplicates).
- **Новое** = прошедшее дедупликацию; **исчезнувшее** = сравнение со snapshot.
- Оповещения: заметка в inbox, email, Telegram-бот.

**Что считать сигналом:**
- новый материал по ключевым словам из настроек;
- новая санкционная запись или новая связь у сущности (`last_change`);
- новый поддомен в crt.sh, изменение ответа Wayback, изменение карточки ГУР;
- **всплеск**: больше N записей за час из одного источника.

Аудит-лог — не отдельный проект: логи скрипта + `raw/*.json` или история выполнений n8n. Главное — чтобы он был и его не чистили.

## Этика, легальность, OPSEC

| Разрешено | Серая зона | Запрещено |
|---|---|---|
| Публичные данные, API по условиям провайдера | Скрапинг сайтов, чьи ToS это запрещают | Взлом, обход аутентификации и CAPTCHA |
| RSS и страницы, которые сайт сам отдаёт; архивные копии | Обход блокировок через прокси-сети и stealth-режимы | Утечки паролей для доступа или давления |
| Уважение robots.txt и rate limits | Персональные данные без правового основания (GDPR, CCPA — реальные штрафы) | Массовый сбор ПДн граждан ЕС без основания |
| Атрибуция источников в отчёте | Коммерческий сбор — только с юристом | Чувствительные цели с рабочего или личного аккаунта |

**OPSEC**: отдельный контур (VM или профиль), отдельные ключи и аккаунты; вендор платформы видит всё, что вы вводите. В рамках хранилища действуем только в колонке «Разрешено»; серая зона и «Запрещено» — для распознавания рисков, не для применения.

## Сравнение инструментов (из лекции)

| Инструмент | Вход → выход | Ограничения |
|---|---|---|
| Low-code (n8n, Make) + API | Название, домен, URL, фид → заметки и отчёт в Obsidian | Ключи API отдельно; лимиты источников |
| Python + requests/BS4 | URL / API-запрос → HTML/JSON | Нужно писать код и обрабатывать данные |
| Telethon (Python) | api_id, api_hash, запрос → сообщения Telegram | Нужен зарегистрированный Telegram-аккаунт |
| Ollama / OpenAI (LLM) | Текст + prompt → структурированный JSON | Лимиты токенов, стоимость |
| Quick OSINT (SaaS, акцент на VK) | Логин VK / телефон → данные профилей, email | Платный RU-сервис, не с рабочих аккаунтов; **вне рамок хранилища** |
| Gaze Bot (Telegram-бот) | Ник Telegram → инфо об аккаунте/канале | Платный RU-бот, **логирует запросы** — OPSEC-риск; вне рамок хранилища |

## Главное для практики

1. Автоматизация ради **воспроизводимости и аудита**, а не скорости.
2. Каждая запись: стабильный id (хеш), `source_url`, `collector`, `query`, `collected_at`, путь к raw.
3. Дубли из разных источников — не подтверждение; дедупликация по id, подтверждение — только независимым источником.
4. Внешний текст в LLM — как **данные в тегах**, не инструкции; ответ — JSON с привязкой red flags к полям.
5. Раздел **«Пробелы»** обязателен; «не установлено» лучше выдумки; отказ сайта фиксируем как данные.
6. Блокировки не обходим: API → RSS → архив (Wayback) → честный UA с паузами.
7. Скриншот — доказательство: страница может измениться или исчезнуть.
8. Мониторинг = пайплайн + расписание + память `seen` + правила сигналов + неочищаемый аудит-лог.
