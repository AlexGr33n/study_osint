# Лекция 08 — Применение теории графов в OSINT

> Название в PDF: «Застосування теорії графів в OSINT», Заняття №8. В программе курса урок 8 значится как «Воркшоп», но сам PDF целиком посвящён графам.

## О чём лекция

Как моделировать объекты расследования (люди, компании, домены, IP, аккаунты) как **вершины**, а их отношения — как **рёбра**, и какие метрики и алгоритмы отвечают на типовые OSINT-вопросы: «кто здесь главный», «кто посредник», «какие тут группировки». Три модуля: где графы применяются в OSINT → базовая теория (понятия, виды, центральности, кластеризация) → инструменты, стек и кейсы.

## Где графы работают в OSINT

| Направление | Что ищем графом |
|---|---|
| **Анализ соцсетей (SNA)** | Влиятельные аккаунты (центральность), сообщества (кластеризация), ботнеты и фейковые аккаунты |
| **Финансовые потоки** | Подозрительные связи между компаниями, офшорные схемы, транзакции компания ↔ человек |
| **Картография киберугроз** | Ботнеты по графу IP / ключевым словам / взаимным упоминаниям; граф зависимостей вредоносного ПО; связи IP и скомпрометированных устройств; корреляция атак и доменов |
| **Домены и IP** | Сетевые связи веб-ресурсов; общие хостинги, провайдеры, SSL-сертификаты; анонимные сети и VPN; **скрытые связи через общие DNS-записи** |
| **Фактчекинг** | Распространение утверждения по сети источников (примеры организаций: Snopes, PolitiFact, Logically, AAP FactCheck) |

Главная мысль лекции: в сложных системах ключевую роль играют **связи, а не только объекты**.

## Базовые понятия

- **Граф** = вершины (vertices / nodes) + рёбра (edges / links). Network = Graph.
- **Типы**: ориентированный (directed — подписка, перевод денег), неориентированный (undirected — «друзья»), взвешенный (weighted — сумма, частота контактов).
- **Примеры**: вершины — люди, компании, продукты, страны (с атрибутами); рёбра — подписка, дружба, иерархическое подчинение; графы — сообщество в соцсети, авиасообщение между городами.
- **Степень вершины (degree)** — число связей; в ориентированном графе **in-degree** (входящие) и **out-degree** (исходящие).
- **Маршрут (path / walk)** — последовательность вершин, повторы допустимы; **замкнутый** — начало = конец; **цикл** — замкнутый без повтора рёбер; **цепь** — незамкнутый без повтора рёбер.
- **Компоненты связности** — группы вершин, связанные внутри, но не между собой. Первое, что стоит посмотреть: изолированные «острова» в данных.

### Терминология в разных дисциплинах

| Дисциплина | Точки | Линии |
|---|---|---|
| Математика | вершины (vertices) | рёбра (edges, arcs) |
| Computer science | узлы (nodes) | связи (links) |
| Физика | объекты (sites) | связи (bonds) |
| Социология | акторы (actors) | отношения (ties, relations) |

### Жаргон ролей в сети

- **Клика (clique)** — подгруппа, где каждый связан с каждым.
- **Кластер** — группа, связанная внутри плотнее, чем с остальной сетью.
- **Посредник (broker)** — связывает разные группы и передаёт между ними информацию.
- **Строитель мостов (bridge)** — вершина/ребро, удерживающее связь двух частей графа (удалишь — граф распадётся).
- **Усилитель (amplifier)** — резко ускоряет распространение информации.
- **Центр** — вершина с минимальным средним расстоянием до всех остальных.

## Виды представления графов

- **Мультиплексный граф** — одни и те же вершины в нескольких слоях-типах связей (на слайде: слои NCAs / Alliances / Conflict). Пример для OSINT: одни и те же люди в слоях «соцсеть», «совместный бизнес», «общий адрес».
- **Overlapping / multilayer graph** — слои с разными, частично пересекающимися наборами вершин (пример: транспорт Rail / Metro / Bus, визуализация MuxViz). Полезно для поиска **пересечения аудиторий** двух сообществ — на слайде это показано мемом-диаграммой Венна про неожиданно большое пересечение двух групп.

## Центральность (centrality) — «кто важен»

| Метрика | Что меряет | OSINT-интерпретация | Пример |
|---|---|---|---|
| **Degree** | Число прямых связей | «Популярность», но не стратегическая роль | Пользователь с наибольшим числом друзей |
| **Closeness** | Обратная средняя длина кратчайших путей до всех | Откуда информация разойдётся быстрее всего | Станция метро, откуда быстрее всего добраться куда угодно |
| **Betweenness** | Как часто вершина лежит на кратчайших путях между другими | **Посредник / мост** между группами — часто самый интересный узел | Человек, соединяющий две разные группы контактов |
| **Eigenvector** | Важен тот, кто связан с важными | Скрытое влияние через «правильные» связи | — |
| **Katz** | Сумма влияний соседей с затуханием на каждом уровне (учитывает «друзей друзей») | Влияние через непрямые связи | — |
| **PageRank** | Ранг по числу **и весу** входящих связей, damping d = 0.85 | Влиятельность источника/аккаунта по цитированию | 85% — переход по ссылке, 15% — случайный прыжок |

**Katz**: C_K(i) = Σ α·A_ij + Σ α²·A_ij·A_jk + … + β, где A — матрица смежности, α — коэффициент затухания (**α < 1/λ_max**, иначе не сходится), β — базовая центральность (малое положительное).
Выбор α на практике: посчитать λ_max матрицы смежности → взять α = 0.85·(1/λ_max) (аналог PageRank) или α = 0.1·(1/λ_max), если непрямые связи должны затухать сильнее.

## Сообщества и кластеризация — «какие тут группы»

**Кластеризация** — разбиение вершин так, чтобы внутри кластеров рёбер было много, а между — мало. Подходы (пример: инфокампании в Facebook):
- **Топологический** — только связи (кто кого репостит/комментирует);
- **Атрибутивный** — только атрибуты вершин (страна, язык, темы);
- **Embedding-based** — гибрид: структурно-поведенческие сообщества (самая полная картина).

**Модулярность (modularity, Q)** — мера качества разбиения на сообщества:
Q = (внутренние связи) − (ожидаемые внутренние связи в случайном графе).
- Q ≈ 1 — чёткие сообщества; Q ≈ 0 — как случайный граф, сообществ нет; Q < 0 — хуже случайного (редко).
- Интуиция: 10 человек, две пятёрки друзей и одна связь между ними — высокая модулярность.
- В формуле: A_ij — матрица смежности, k_i, k_j — степени, m — число рёбер, δ(c_i, c_j) = 1, если вершины в одном сообществе.

### Алгоритмы поиска сообществ

| Алгоритм | Идея | Когда |
|---|---|---|
| **Girvan–Newman** | Повторять: пересчитать edge betweenness → удалить ребро с наибольшей «мостовостью» → пока граф не распадётся на сообщества | Небольшие графы, наглядно; дорого на больших |
| **Louvain** | 1) локальная оптимизация: каждая вершина переходит в соседнее сообщество, если растёт Q; 2) агрегация сообществ в супер-узлы, повтор. Иерархический, быстрый, масштабируется | Именно он стоит за **Gephi → Statistics → Modularity** |
| **Leiden** | Как Louvain + шаг **refinement**: дробит найденные сообщества, убирая «ошибочные» слияния (слабо связанные куски) → агрегация | Предпочтительнее Louvain: сообщества гарантированно связные |

**Статистическая инференция на графах** — вероятностные модели и проверка гипотез вместо «как нарисовалось»: поиск структур (сообщества, кластеры, **аномалии**), восстановление скрытых связей, моделирование вероятностных структур, бенчмаркинг алгоритмов.

## Практический смысл: какую метрику под какой вопрос

- **Кто в каких группах?** → модулярность (Louvain), Leiden, Girvan–Newman.
- **У кого больше всего связей?** → степень (degree).
- **Кто реально влиятелен?** → Katz, eigenvector, PageRank.
- **Кто посредник / мост?** → betweenness.
- **Вес узла** — дополнительный составной параметр влиятельности и роли (например, суммы, частота контакта).

## Инструменты и стек

| Инструмент | Назначение |
|---|---|
| **NetworkX** (Python) | Анализ графов в коде: метрики, сообщества |
| **Gephi** | Визуализация и исследование; Statistics: avg degree, diameter, density, HITS, modularity, PageRank, connected components, Girvan–Newman, Leiden, clustering coefficient, eigenvector |
| **Graphistry** | GPU-визуализация очень больших графов |
| **Neo4j** | Графовая БД (хранит узлы с метками, напр. `[Person, Customer]`, связями и свойствами); альтернативы — **Memgraph**, **TigerGraph** |
| **pandas + NumPy** | Подготовка таблиц рёбер/узлов, матрицы смежности, линейная алгебра |
| OSINT-инструменты с графами | **Maltego**, **SpiderFoot**, **Linkurious** |

Типовой стек из лекции: **Neo4j + pandas + NumPy + Gephi** (хранение → подготовка → анализ → визуализация).

## Кейсы

- **Прогноз ЧМ-2022 по футболу** — граф «сборная ↔ клубы игроков»: размер узла сборной отражает связанность её игроков с топ-клубами (Франция — крупнейший узел).
- **Сеть Дональда Трампа** (Cambridge Intelligence, «Untangling the hairball») — из нечитаемого «клубка» (hairball) выделяется путь через посредников: Путин → Лев Леваев → Africa-Israel Investments → Kushner Companies → Deutsche Bank → DJT Holdings. Урок: **ценность — в пути между узлами, а не в общей картинке**; без фильтрации и выделения путей большой граф бесполезен.

## Ограничения метода (из выводов, тезисно)

- Граф отражает только собранные связи: пропуски в данных = ложная «изоляция» или ложный «посредник».
- Красивая картинка ≠ вывод: метрику и алгоритм нужно выбирать под вопрос и проверять (инференция, сравнение алгоритмов).
- Ребро из графа — гипотеза о связи, которую нужно подтвердить источником (грейд достоверности).

## Главное для практики

1. Сначала сформулируй вопрос (кто главный / кто посредник / какие группы), потом выбирай метрику.
2. **Betweenness** — лучший кандидат на «скрытое звено» между группами; проверяй такие узлы в первую очередь.
3. Для сообществ используй **Leiden** (или Louvain в Gephi), смотри на Q: при Q ≈ 0 сообществ нет.
4. Разные типы связей держи **слоями** (multiplex), не сваливай в один граф.
5. Начинай с компонент связности и ищи пути между интересующими узлами, а не разглядывай hairball.
6. Каждое ребро должно иметь источник и дату — иначе граф неаудируем.
7. Стек для учёбы: pandas → NetworkX → Gephi; для больших/постоянных данных — Neo4j.
8. В рамках хранилища граф строится только из законных публичных источников и не используется для профилирования частных лиц без авторизации.
