# Б1 — Промпт A/B тест

**Об'єкт:** Макс Іщенко (Max Ischenko) — засновник українських IT-платформ **DOU.ua**
(спільнота і медіа для розробників) та **Djinni.co** (сервіс пошуку роботи для IT).
Публічна, верифікована особа, але не медіаперсона федерального рівня — рідко дає інтерв'ю.

**Модель:** Claude Opus 4.8 (claude-opus-4-8).
**Та сама людина, та сама модель — різниця лише в промпті.**

Публічні джерела про особу (для контексту):
[DOU.ua профіль](https://dou.ua/users/) ·
[dev.ua](https://dev.ua/news/dou-djinni-1711384767) ·
[подкаст «1-2-3 Techno», 19.04.2024](https://dou.ua/lenta/articles/1-2-3-techno-max-ischenko/)

## Крок 1. «Поганий» промпт

> **Промпт (повний текст):**
>
> ```
> Розкажи мені про Макса Іщенка
> ```

Без ролі. Без формату. Без джерел. Без обмежень. Без заборони вигадувати.

### Відповідь LLM (з пам'яті, без пошуку — повний текст)

> Макс Іщенко — український IT-підприємець, один із найвідоміших людей в українській
> технологічній спільноті. Він найбільше відомий як засновник порталу **DOU.ua**
> (Developers.org.ua) — найбільшої онлайн-спільноти та медіа для IT-фахівців в Україні,
> яку він запустив приблизно у 2005–2006 роках. Згодом він створив **Djinni** — сервіс
> пошуку роботи для розробників, де рекрутери та компанії самі пишуть кандидатам, а не
> навпаки. Djinni з'явився орієнтовно у 2012–2013 роках і став дуже популярним.
>
> Іщенко має репутацію продуктового підприємця, який цінує невеликі ефективні команди.
> Він доволі закрита людина, рідко дає інтерв'ю та нечасто з'являється в медіа. За освітою
> він, найімовірніше, програміст; імовірно, навчався у Києві. Живе і працює в Україні.
> Його часто згадують серед піонерів українського IT-ринку, адже DOU фактично
> сформував культуру відкритих зарплатних даних і рейтингів компаній у галузі.

### Що не так із цією відповіддю

- **Немає джерел** — жодне твердження не можна перевірити одразу.
- **Впевнені, але неточні деталі:** роки заснування подані «вилкою» (2005–2006, 2012–2013),
  бо модель не пам'ятає точно — але звучить упевнено.
- **Вигадані/недоведені поля:** «за освітою програміст», «навчався у Києві», «живе в Україні» —
  це домисли, у відповіді немає маркера невпевненості.
- **Немає структури** — неможливо автоматично витягти поля чи передати далі у пайплайн.
- **Немає `null`** — модель не каже «невідомо», а заповнює прогалини здогадами.

## Крок 2. Структурований промпт (фреймворк P-R-O-M-P-T)

Той самий об'єкт — але з **роллю (Persona), завданням (Request), форматом (Output),
обмеженнями (Measures/constraints), контекстним текстом (Primary text)** і забороною вигадувати.

> **Промпт (повний текст):**
>
> ```
> Ти — аналітик OSINT. Витягни з наведеного нижче тексту інформацію про особу.
>
> Поля: full_name, current_position, organization, education, public_contacts,
> career_timeline (масив об'єктів {year, role, org}).
>
> Формат виводу: валідний JSON. Лише факти, явно підтверджені в тексті.
> Якщо поле не згадане в тексті — постав null (для масиву — []).
> Не додавай знань ззовні тексту. Не вигадуй деталей. Не роби домислів.
> Для кожного факту він має бути дослівно простежуваним до тексту.
>
> Текст:
> """
> Max Ischenko (Макс Іщенко). Founder.
> Headline: Founder at DOU.ua & Djinni.co. Startups, product, Python.
>
> About: I build products for the tech community. Founder of DOU.ua, the largest
> online community and media site for software developers in Ukraine. Founder of
> Djinni.co, a job-search service for developers (candidates stay anonymous,
> companies reach out first).
>
> Experience:
> - Founder, DOU.ua — from April 2005 to present
> - Founder, Djinni.co — from January 2013 to present
> - Producer & host, "Profit Show" (talk show about tech entrepreneurs) — 2012
> - Founder, vse-sto.com.ua — 2009 to 2010 (sold in 2011)
> - Consultant/Developer, Juice Analytics — 2006
> - Developer, Polimetrix — 2005
>
> Skills: Start-ups, Software Development, Python.
> Links: x.com/maxua
> """
> ```

> **Примітка про текст.** Наведений блок — це реконструйований публічний профіль
> у стилі LinkedIn/mentor-картки (архівна mentoryio-картка Макса Іщенка, що дзеркалила
> його LinkedIn; на момент виконання ДЗ сторінку закрито). Факти кар'єрного таймлайну
> взяті саме з неї; поля «освіта», «email/телефон», «поточне місто» в тексті **свідомо
> відсутні** — щоб показати, як коректна модель повертає `null`, а не вигадує.

### Відповідь LLM (повний текст)

```json
{
  "full_name": "Max Ischenko (Макс Іщенко)",
  "current_position": "Founder",
  "organization": ["DOU.ua", "Djinni.co"],
  "education": null,
  "public_contacts": {
    "x_twitter": "x.com/maxua",
    "email": null,
    "phone": null,
    "city": null
  },
  "career_timeline": [
    { "year": "2005",      "role": "Developer",            "org": "Polimetrix" },
    { "year": "2006",      "role": "Consultant/Developer", "org": "Juice Analytics" },
    { "year": "2005–present", "role": "Founder",           "org": "DOU.ua" },
    { "year": "2009–2010", "role": "Founder (sold 2011)",  "org": "vse-sto.com.ua" },
    { "year": "2012",      "role": "Producer & host",      "org": "Profit Show" },
    { "year": "2013–present", "role": "Founder",           "org": "Djinni.co" }
  ]
}
```

Модель повернула `education`, `email`, `phone`, `city` як `null` — бо цих даних **немає
в тексті**. Вона не додала «за освітою програміст» чи «живе в Києві», хоча у Кроці 1
саме так і зробила.

## Крок 3. Порівняння двох відповідей

| Критерій | Поганий промпт | Структурований промпт |
|---|---|---|
| Структура | суцільний текст, не парситься | валідний JSON, готовий у пайплайн |
| Джерело фактів | «пам'ять» моделі, не відстежувана | лише наданий текст, відстежувано |
| Вигадані поля | є (освіта, місто) | немає |
| Поведінка за браком даних | заповнює здогадом | ставить `null` |
| Точність дат | «вилки» 2005–2006, 2012–2013 | точні з тексту (04.2005, 01.2013) |
| Придатність для OSINT-звіту | низька (треба все перевіряти) | висока (факти вже прив'язані до джерела) |
| Ризик галюцинації | високий | мінімізований обмеженнями |

## Висновок (Б1)

Та сама людина і та сама модель дали дві принципово різні за якістю відповіді — різниця
лише в тому, що я написав у запиті. Поганий промпт змусив модель заповнити прогалини
впевненими домислами (освіта, місто проживання) без жодного джерела; структурований
промпт із роллю, JSON-форматом і правилом «немає в тексті → `null`» прибрав вигадки й дав
машиночитаний результат, кожне поле якого простежується до вихідного тексту. Найсильніше
здивувало, наскільки дешево досягається надійність: достатньо явно заборонити домисли і
задати `null` як дефолт. У реальну роботу заберу принцип «модель витягує з наданого
тексту, а не згадує зі своєї пам'яті» — це перетворює LLM із «оповідача» на керований
екстрактор.
