# Паттерны, тренды и кластеризация

Источник: курс «AI для OSINT 2026», лекция 13 (Neo4j и Gephi на Elliptic++; прежняя версия урока — матрица
активности, BERTopic), лекция 17 (статистика) и лекция 8 (конспекты в хранилище). Загружай на Фазе 3, когда из массива — граф переводов
или связей, корпус постов, метки времени — нужно извлечь структуру. Метрики графа под вопрос и правило 2+ —
в `entity-resolution.md`.

## Главное правило

Паттерн, кластер и тренд — **гипотезы для проверки вне данных**, а не вывод. Каждый оформляется так, чтобы другой
аналитик повторил его:

| Что | Воспроизводимая форма |
|---|---|
| Паттерн | Запрос (Cypher/SQL/pandas) с порогами и обоснованием порогов |
| Кластер | Алгоритм + параметры (γ, веса, ориентация) + версия данных |
| Тренд | Метрика во времени + нормировка + проверка дрейфа + наложенные события |
| Рисунок | Подграф + фильтры + layout + палитра + сохранённый проект |

## Пороги — от данных, а не «на глаз»

- **Базовая доля (base rate):** доля признака во всём наборе (напр. illicit среди кошельков — 1,7 %).
- **Lift** = доля в группе / базовая. Группа интересна, когда lift в разы выше 1, а не когда «много красного».
- **Перцентили** для степеней и сумм: порог fan-in = p99.9 (на Elliptic++ p99 / p99.9 / max = 46 / 103 / 11 213).
- **Доли по периодам — через суммы**, а не как среднее процентов по шагам.
- **Проверка на избирательность:** если условие ловит половину набора, это не сигнатура (peel chain «2 выхода,
  малый < 10 %» — 50 % транзакций Elliptic++).
- Порог записывается в методологию вместе с тем, сколько записей он отсёк.

## Паттерн → сигнатура → легитимное объяснение

| Паттерн | Сигнатура | Легитимное объяснение (исключить до вывода) |
|---|---|---|
| Fan-in (консолидация) | Входящая степень ≫ медианы | Биржа, пул, сбор донатов, агрегатор |
| Fan-out (распыление) | Исходящая степень ≫ медианы | Пакетные выплаты, зарплаты, рассылка |
| Цепочка / peel chain | ≥ 5 шагов подряд, малый «отщеп» + остаток дальше | Обычный кошелёк со сдачей |
| Цикл (round-trip) | Возврат к старту за 2–4 шага | Переводы между своими счетами; транзит через сервис |
| Смешивание (CoinJoin) | Много входов, равные выходы | Желание приватности |
| Мост / хаб | Высокая betweenness между сообществами | Биржа, платёжный шлюз, медиа-агрегатор |
| Плотное ядро | k-core, высокая модулярность | Реальное сообщество, а не координация |

Для соцграфов то же: одни и те же аккаунты репостят вместе → плотный подграф (кандидат в бот-сеть), но и фан-клуб.
На Elliptic++ кошельки с fan-in ≥ 100 оказались illicit реже среднего (0,9 % против 1,7 %): **сильная структура
чаще указывает на сервис, чем на преступление**.

Проверяй, что запрос ловит именно паттерн: шаблон peel chain, проверяющий только форму каждой транзакции, не
гарантирует, что цепочка идёт через больший выход.

## «Кластер» — три разных утверждения

| Тип | Вопрос | Метод | Ошибка, которой бояться |
|---|---|---|---|
| Кластер адресов / записей (entity resolution) | Один ли владелец? | Эвристики, сильные якоря | Ложное слияние — необратимо |
| Сообщество (community detection) | Кто связан плотнее, чем случайно? | WCC → Louvain / Leiden | Супервузлы склеивают сообщества |
| Поведенческий кластер (feature clustering) | Кто ведёт себя похоже? | k-means на признаках, FastRP | Похожесть ≠ связь |

В отчёте называй тип. Эвристики кластеризации крипто-адресов — `entity-resolution.md` §Кластеризация крипто-адресов.

## От сообщества к лиду

1. Сообщества (Louvain / Leiden на неориентированной взвешенной проекции); супервузлы бирж и сервисов пометить или
   исключить **до** запуска; записать γ и веса. Номера сообществ меняются от запуска — сравнивай размеры и доли.
2. Отобрать сообщества с lift ≫ 1 (напр. доля ≥ 10 % при базовой 1,7 %).
3. Кандидаты — неразмеченные узлы внутри, ранжированные по PageRank.
4. Структурное подтверждение вокруг кандидата: fan-in, цепочки, экспозиция (сколько «плохих» узлов доходит за 1–2 шага).
5. Офчейн-проверка: форумы, метки обозревателей (грейд B–C), санкционные списки, отчёты.
6. Вывод: уровень уверенности, альтернативное объяснение, ограничения данных.

**Независимость сигналов:** сообщество и экспозиция считаются по одним и тем же рёбрам — это почти один сигнал.
Независимая пара — **структура + офчейн-атрибуция**. Одинаковая экспозиция у нескольких узлов — подсказка, что это
адреса одного сервиса. **Лид — объект для проверки, а не подозреваемый; близость ≠ причастность.**

## Тренды и дрейф

- **Нормируй:** активность / возраст узла, суммы — в фиксированную валюту по курсу периода; сравнивай скорости,
  а не абсолютные суммы.
- **Качество моделей и правил — по срезам времени, а не в среднем.** После скачка (закрытие рынка, санкции, арест,
  ребрендинг сервиса) старые паттерны и классификаторы слепнут (Elliptic: после шага 43 ни один метод не находил
  новые illicit-транзакции).
- **Накладывай события на шкалу** — тренд без контекста лишь кривая.
- **Альтернативы падения/роста:** запаздывание разметки (новые площадки ещё в unknown), смена источника данных,
  изменение охвата сбора, сезонность, отложенный постинг.
- **Сравнение периодов по текстам:** TF-IDF обучать на объединении периодов (словарь, обученный на первом окне,
  не видит новых терминов) либо считать частоты по неделям как временной ряд.
- **Детекторы аномалий** (Isolation Forest) объявят аномальной заданную долю `contamination` при любых данных —
  каждый найденный день открывай и читай.

## Всплеск: кампания или органика (статистика, лекция 17)

Значимый рост показывает «необычно», а не «скоординировано»: реакция аудитории на событие тоже даёт значимую разницу.

1. **Базовый период** отдельно от подозрительного. По нему медиана, IQR и граница Тьюки `Q3 + 1,5·IQR`;
   дни выше границы — кандидаты. Каждый открыть и сравнить по **вторичным признакам** (просмотры, доля репостов,
   доля молодых каналов): органический всплеск и кампания различаются ими, а не объёмом.
2. **Сравнение периодов:** размер эффекта (разница, во сколько раз) и доверительные интервалы рядом с p-value.
   Дневной ряд автокоррелирован — дни не независимы, обычный тест завышает значимость (проверить лаг-1). Несколько
   метрик → Бонферрони (α / k) или FDR. При выбросах — непараметрический тест как проверка устойчивости.
3. **Корреляция:** Пирсон — линейная, Спирмен — монотонная и при выбросах. Пересчитать без дней-всплесков и
   только на базовом периоде; связь, которая есть лишь на полном ряду, часто держится на третьей переменной.
4. **Байес:** prior записан явно, обновление по шагам (`posterior odds = prior odds × LR`). Зависимые признаки
   (новые каналы чаще репостят) не перемножать как независимые — для второго брать правдоподобие при условии
   первого; иначе одни и те же доказательства засчитываются дважды. Итог — словом из одной шкалы отчёта.
5. **Кластеры на признаках:** k-means делит на K групп даже равномерный шум; DBSCAN оставляет шум шумом и
   ловит группы произвольной формы. Число и форма кластеров — гипотеза, а не находка.
6. **Формулировки:** «результаты свидетельствуют в пользу», n и состав выборки, обработка пропусков, проверка на
   подвыборках. Отсутствие наблюдений (провал сбора, «фотопробел») ≠ отсутствие события.

## Время в текстовых корпусах

- Матрица «день недели × час» по одним меткам времени: храни UTC, подписывай пояс оси; пик активности — гипотеза
  о часовом поясе (отложенный постинг, боты и летнее время её искажают). Только для каналов, организаций и
  публичных ролей.
- Тематическая кластеризация (BERTopic: эмбеддинги → UMAP → HDBSCAN → c-TF-IDF): названия темам даёт аналитик;
  для смешанных языков — мультиязычная модель.

## Метки датасетов и ML-оценки

- **unknown ≠ licit / benign.** Неразмеченное — пространство гипотез.
- Метки, извлечённые LLM из форумов, — грейд C до второго независимого источника; конфликт меток в кластере → без метки.
- ML-прогноз типа сущности — **очередь проверки, а не атрибуция**. Считай точность, а не только полноту:
  P = F1·R / (2R − F1) (ransomware в бенчмарке: R = 0,60, F1 = 0,32 → P ≈ 0,22 — 4 из 5 срабатываний ложные).

## Научная статья — тоже источник

Пересчитывай ключевые цифры до цитирования (в препринте BitcoinTemporalGraph плотность «≈ 1 %» при реальных
1,2·10⁻⁸; сумма таблиц не совпала с текстом на 2 433). Проверяй атрибуцию источников (SDN ведёт OFAC, а не Минюст).

## Визуализация как доказательство

Подпись к каждому рисунку графа:
1. Легенда цветов и размеров.
2. Источник данных, дата, версия датасета.
3. Что отфильтровано и почему (фильтр — часть методологии).
4. Параметры layout и сохранённый проект (`.gephi`).
5. Метки — данные датасета, а не установленные факты.
6. Вектор (SVG/PDF).

Одинаковые layout и палитра для всех рисунков отчёта. Чтение формы: плотное ядро → сообщество; звезда → хаб;
длинная нить → цепочка; узел между группами → мост; остров → компонента.

## Инструменты (кратко)

- **Хранение:** большой массив — SQL; подграф расследования — Neo4j (многошаговые пути, паттерны, GDS).
- **Neo4j:** ограничения уникальности **до** импорта; `LOAD CSV … CALL { } IN TRANSACTIONS` (в Browser — `:auto`);
  преобразования CSV — скриптом рядом с данными; порты публиковать на `127.0.0.1`.
- **GDS:** проекция → `*.estimate` → алгоритм (`stream` / `stats` / `mutate` / `write`) → анализ в Cypher →
  `gds.graph.drop`. WCC → Louvain/Leiden → PageRank, betweenness (дорого — на подграфе), degree, FastRP + k-means.
- **Экспорт:** APOC (`apoc.export.graphml.query`, `apoc.export.csv.query`, нужен `apoc.export.file.enabled=true`);
  CSV с колонками `Id` / `Source`, `Target`, `Weight` Gephi распознаёт сам.
- **Gephi:** Statistics (Degree, Modularity, PageRank, Connected Components) → ForceAtlas2 (LinLog, Dissuade Hubs,
  Prevent Overlap в конце) → фильтры (Ego, Giant Component, K-core, Partition, Time Interval) → Preview → SVG.
  Timeline — колонки `start`/`end` → Create time interval. Gephi Lite (браузер) — для небольших графов.

## Антипаттерны

1. Порог «на глаз» без базовой доли и перцентиля.
2. Паттерн без легитимного объяснения — сразу в вывод.
3. «Кластер» без указания, какой из трёх.
4. Два «независимых» сигнала, посчитанных по одним рёбрам.
5. Запуск сообществ, не убрав супервузлы бирж и сервисов.
6. Метрика качества в среднем по времени вместо срезов; тренд без событий.
7. unknown считать чистым; ML-score или метку датасета — атрибуцией.
8. Рисунок без легенды, фильтров и параметров — не доказательство.
9. Деанонимизация физлиц за адресами или поведенческое профилирование частных лиц — вне рамок навыка.
