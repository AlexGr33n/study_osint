# Методология — пошаговый плейбук по фазам

Подробный рабочий чек-лист для фаз из `SKILL.md`. Загружай, когда тебе нужна
механика, а не философия.

## Фаза 0 — Рамки и план

**Результат: письменный план до любого поиска.**

- [ ] **Исследовательский вопрос** в одно предложение. Конкретный и отвечаемый.
- [ ] Указаны **цель и авторизация** (см. `ethics-and-legal.md`).
- [ ] Перечислены **источники в рамках (scope)**; те, что вне рамок, названы явно.
- [ ] Собраны **стартовые идентификаторы**: имя/ник, домен, IP, email, телефон, изображение, URL, ID дела.
- [ ] Определено **условие остановки** (как выглядит «отвечено» — например, «2 подтверждения грейда A»).
- [ ] Создан **рабочий файл** для журнала запросов, URL и находок по ходу дела.

Ловушка: расплывчатый вопрос («найти всё про X») порождает безграничное, неэтичное
и низкокачественное расследование. Сужай его, пока у него не появится ответ.

## Фаза 1 — Сбор (сначала вширь)

**Цель: широкая сеть кандидатов-источников, у каждого записано происхождение (provenance).**

Работай параллельно, где возможно; начинай с бесплатного и открытого.

1. **Идентичность / веб-стартовые идентификаторы**
   - Широкий веб-поиск + поиск по новостям по точному идентификатору (используй кавычки для точных фраз).
   - Добавь уточнитель (организацию, город, домен), чтобы рано отсеять однофамильцев.
   - Отмечай кандидатов-профили/страницы — пока не атрибутируй, просто собирай.
2. **Технические стартовые идентификаторы** (домен, IP, email, имя пользователя) → см. `sources.md` §Инфраструктура и §Аккаунты.
3. **Медиа-стартовые идентификаторы** (изображение, видео) → см. `sources.md` §Медиа и геолокация. Сначала — происхождение (provenance).
4. **Записывай по ходу:** для каждого попадания фиксируй `url | как найдено | первое впечатление | на верификацию?`.

Дисциплина:
- Разноси запросы во времени; уважай лимиты частоты; один запрос за раз на сервис в плотных циклах.
- Предпочитай первичные/авторитетные источники (реестры, официальные записи) агрегаторам.
- Не иди по цепочке ссылок в непубличную зону — останавливайся на линии контроля доступа.

## Фаза 1.5 — Ранее известное (только если законно принадлежит тебе)

Если расследование ведётся по **твоему собственному** цифровому следу, по **согласному**
субъекту или в рамках **авторизованного взаимодействия**, где у тебя уже есть записи, сначала
проверь то, что у тебя уже имеется, чтобы избежать избыточного сбора. Это *не* лицензия
выуживать частные коммуникации о третьих лицах — см. `ethics-and-legal.md`.

## Фаза 2 — Верификация

**Цель: превратить утверждения в факты с грейдом.** Для каждого факта-кандидата:

1. **Подтверди.** Найди второй *независимый* источник. Остерегайся синдикации — 20 сайтов,
   перепечатавших один пресс-релиз, — это один источник, а не двадцать.
2. **Разреши идентичность.** Докажи, что оба источника об одной и той же сущности:
   - Совпадение по 2+ стабильным атрибутам (уникальный ник + организация, фото + запись в реестре и т.д.).
   - Если не можешь — раздели на отдельные сущности-кандидаты и держи их порознь.
3. **Присвой грейд** A/B/C/D (определения в `verification.md`).
4. **Фиксируй противоречия** с обоими источниками; никогда не разрешай их по предпочтению.

Переходи к проверкам подлинности для любого медиа или аккаунта, который имеет значение (`verification.md` §Подлинность).

## Фаза 3 — Анализ

- **Таблица фактов:** каждое утверждение — строка — `утверждение | источник(и) | грейд | заметки`.
- **Таймлайн:** упорядочь события с грейдом; пробелы и наложения — это находки.
- **Карта** (когда уместно): граф инфраструктуры (домены↔IP↔регистранты) или
  граф связей — узлы/рёбра только из фактов с грейдом.
- **Журнал выводов (инференсов):** держи выводы в отдельном списке от наблюдений, у каждого —
  уровень достоверности и доказательства, на которых он держится.
- **Поведенческие/авторские заметки:** только как гипотезы атрибуции с оговорками (см. `SKILL.md` Фаза 3).

## Фаза 4 — Отчётность

Следуй `assets/report-template.md`. Чек-лист:
- [ ] Ответ на вопрос заявлен первым, с общей достоверностью.
- [ ] Каждая находка несёт источник + грейд.
- [ ] Противоречия показаны, а не спрятаны.
- [ ] Явный раздел пробелов/неизвестного.
- [ ] Метод и рамки (scope) записаны (воспроизводимо/проверяемо).
- [ ] Ноль утверждений без источника.

## Фаза 5 — Самооценка (рекурсивный цикл)

1. Прогони **проверки покрытия** (прошло/не прошло) из `SKILL.md`.
2. Вычисли **оценку глубины (1–10)**, взвешивая оси, которые важны для твоего вопроса.
3. Диагностируй слабейшую ось:
   | Ситуация | Действие |
   |---|---|
   | Высокая глубина, проверка покрытия провалена | Целься в этот конкретный пробел, ещё один цикл |
   | Низкая глубина, всё покрытие пройдено | Углубляйся: лучше источники, больше подтверждений |
   | Противоречие не разрешено | Новый угол/источник специально, чтобы разбить ничью |
   | Плато (мало прироста 2 цикла подряд) | Останавливайся; сдавай с честными ограничениями |
4. **Условия остановки:** достаточная глубина + всё покрытие пройдено; или 3 цикла; или плато.

## Параллельная работа («рой») — когда и как

Для большого авторизованного расследования ты можешь разбить независимые подзадачи по
параллельным субагентам (например, по одному на категорию источников), а затем слить. Правила:
- Только для **авторизованной работы в рамках (scope)** — параллелизм усиливает и скорость, и риск.
- Каждая подзадача получает те же рамки (scope), стартовые данные и этические ограничения.
- Каждая пишет находки с происхождением (provenance) в свой файл; координатор сливает и
  прогоняет Фазы 2–5. Параллель — для *сбора*, никогда для *суждения*: верификация остаётся централизованной.
