# Сигнал формы транзакции без меток

Сигналы из меток соседей (экспозиция, сообщество) тянут одну и ту же разметку.
Независимый второй сигнал можно взять из **формы** транзакции, где метки не участвуют вообще: число входов и выходов, есть ли сдача, тратятся ли деньги дальше.

## Пример: консолидация + sweep

Транзакция с одним выходом и десятками входящих потоков переводит весь собранный баланс на новый адрес без сдачи.

```cypher
MATCH (t:Transaction)-[:OUTPUT]->(w:Wallet)
WHERE t.nOut = 1 AND COUNT { ()-[:FLOWS_TO]->(t) } >= 20
WITH DISTINCT w
RETURN count(*) AS wallets,
       round(100.0 * count(CASE WHEN w.class = 1 THEN 1 END) / count(*), 1) AS illicitPct;
```

На Elliptic++ таких получателей 171, illicit среди них 12,9 % против базовых 1,73 % (lift ≈ 7,5).
Значит, форма сама по себе несёт информацию. Lift сигнала надо **посчитать** на всём датасете, а не принять на веру.

## Ограничения

- Та же форма у легальных сервисов: биржа сметает депозитные адреса в горячий кошелёк.
  Поэтому сигнал формы — второй, а не единственный.
- Elliptic++ хранит не все входы: у транзакции из ДЗ-13 `num_input_addresses` = 29, а рёбер `INPUT` от кошельков всего 1. Считай по `FLOWS_TO`.
- Метки кошельков Elliptic++ выведены из меток транзакций: unknown-кошелёк никогда не участвует в illicit-транзакции, так что «получил из illicit-транзакции» как сигнал для unknown невозможен.
