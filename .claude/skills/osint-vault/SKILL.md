# Учебное хранилище OSINT

Превращай каждое расследование и каждый урок в связанные, переиспользуемые заметки. Смысл
учебного хранилища в том, чтобы твоё *второе* расследование определённого рода шло быстрее первого.

Корень хранилища: хранилище Obsidian в каталоге `study_osint/`. Создавай заметки там (не в `skills/`).

## Типы заметок

Каждая заметка объявляет свой `type` во фронтматтере и живёт по простому соглашению.

| type | Назначение | Пример имени файла |
|---|---|---|
| `technique` | Повторяемый метод (геолокация по обратному поиску изображения, охота за поддоменами по CT-логам) | `Reverse image geolocation.md` |
| `tool` | Конкретный инструмент/сервис: что делает, входные данные, ограничения, когда применять | `WHOIS-RDAP lookup.md` |
| `source` | Категория источника/датасета и то, для чего он авторитетен | `Certificate Transparency logs.md` |
| `practice-log` | Разбор практического прогона / CTF / упражнения по своему цифровому следу | `2026-09-30 Geo CTF - harbor photo.md` |
| `report` | Готовый отчёт о расследовании (по шаблону osint-research) | `Report - domain attribution acme.md` |
| `asset` | Типизированный актив графа активов: узел `type`/`key`/`value` с источниками и достоверностью (домен, поддомен, IP, ASN, облачная корзина, email-паттерн). Только публично наблюдаемое, с трека «только обнаружение (discover-only)». | `Asset - domain acme.com.md` |
| `finding` | Карточка находки — то, что владелец актива должен починить: критичность × достоверность, `asset_key`, доказательства (provenance), рекомендация по устранению. Категория exposure, а не шаги эксплуатации. | `Finding - exposed env acme-app.md` |
| `moc` | Карта контента (MOC): индексная заметка, связывающая тематический кластер | `OSINT MOC.md` |
| `concept` | Принцип/определение (грейд достоверности, независимость, минимизация данных) | `Confidence grading A-B-C-D.md` |
| `lecture` | Конспект лекции курса: смысловые блоки, фреймворки, инструменты, «Главное для практики», ДЗ, связи. Живёт в `Лекции/`, фронтматтер добавляет `lecture: N` | `Лекции/Лекция 07 — Entity resolution и графы связей.md` |

## Схема фронтматтера

Держи её небольшой и единообразной, чтобы Obsidian Properties / Bases и Dataview могли по ней делать запросы.

```yaml
---
type: technique        # один из типов выше
tags: [osint, geolocation]
status: seed           # seed | growing | evergreen
source: "{откуда узнал — url/курс/кейс, необязательно}"
created: 2026-09-30
updated: 2026-09-30
---
```

Для `practice-log` / `report` добавь:
```yaml
difficulty: "{easy|medium|hard}"
skills_used: [reverse-image, chronolocation]
outcome: "{solved | partial | insufficient-data}"
ethics_check: passed        # явно — каждая заметка о практике подтверждает, что gate удержался
# необязательно — если прогон дал находки (только для авторизованной работы):
severity: "{info|low|medium|high|critical}"   # критичность самой серьёзной находки прогона
confidence: "{A|B|C|D}"                        # её грейд достоверности
asset_key: "domain:acme.com"                   # к какому активу графа она привязана
```

Для `asset` добавь (типизированный актив графа активов — только публично наблюдаемое):
```yaml
type: asset
asset_type: domain            # domain | subdomain | ip | asn | cloud-bucket | email-pattern | cert
key: "domain:acme.com"        # стабильный ключ узла: <asset_type>:<value>
value: "acme.com"
sources: ["[[Certificate Transparency logs]]"]  # чем подтверждён; викиссылки на source-заметки приветствуются
confidence: A                 # грейд достоверности A/B/C/D
first_seen: 2026-09-30
last_seen: 2026-09-30
```

Для `finding` добавь (карточка находки; тело заметки несёт доказательства и рекомендацию по устранению):
```yaml
type: finding
severity: medium              # критичность: info | low | medium | high | critical
confidence: B                 # грейд достоверности A/B/C/D
asset_key: "domain:acme.com"  # к какому активу графа относится находка
```

## Раскладка доказательств для авторизованной работы

Только для **авторизованной** работы (`ethics_check: passed`) — учебный трек по своему
цифровому следу, задача CTF или проект с записанными рамками (scope) и пройденным gate
авторизации. Для чистого учебного конспектирования это лишнее.

Когда прогон порождает артефакты (скриншоты, сохранённые HTML, экспорты запросов, дампы
ответов коннекторов), держи их рядом с заметкой работы, разложив по стадиям трека поверхности
атаки — так происхождение (provenance) остаётся привязанным к стадии, на которой ты это увидел:

```
<работа>/
  <работа>.md                 ← заметка report / practice-log
  ev/
    stage1-seed/              ← затравка (seed): стартовые идентификаторы, исходный scope
    stage2-expansion/         ← расширение активов: узлы графа, найденные от затравки
    stage3-enrichment/        ← обогащение: публичный контекст по активам (категоризация, открытые записи)
```

- Рядом с каждым артефактом клади файл `<имя>.sha256` с его хешем — это фиксирует **цепочку
  происхождения (chain of custody)**: что ты видел, в каком виде и когда, ещё до любых правок.
- Артефакт неизменяем. Аннотации, наблюдения и выводы (инференс) живут в заметке, а не поверх
  доказательства — это и есть **гигиена доказательств**.
- Раскладывай по *стадиям*, а не по типам файлов: ценно то, **на каком шаге** появился актив.
- Полную дисциплину гигиены доказательств см. в `osint-research/references/tradecraft.md`.

Трек поверхности атаки здесь — **только обнаружение (discover-only)**: он заканчивается на
пассивном/публичном наблюдении. Дальнейшие стадии (анализ уязвимой поверхности → схождение →
отчётность) работают с уже собранными публичными данными и производят карточки `finding` —
описания категорий exposure для владельца, без шагов эксплуатации. «Активная проверка» (active
validation) активов — **вне рамок навыка**: она требует отдельной письменной авторизации, правил
взаимодействия (RoE) и лежит за пределами OSINT.

## Дисциплина связывания (именно в ней вся ценность)

- **Ставь викиссылки щедро.** Заметка `technique` ссылается на `tool` и `source`, которые она
  использует; `practice-log` ссылается на каждую технику/инструмент, что были задействованы;
  `report` ссылается на свои методы. Ссылка `[[link]]` на ещё не существующую заметку — это нормально:
  она отмечает заметку, которую стоит написать.
- **Обратные ссылки (backlinks) — это твоя учебная карта.** Открой заметку `technique`, и её
  обратные ссылки покажут каждый случай, где ты действительно её применял — это твоё доказательство
  владения и твой список для повторения.
- **Связывай находки с активами и практикой:** `finding` ↔ `asset` ↔ `practice-log`/`report`.
  Карточка `finding` ссылается на свой актив (викиссылкой и полем `asset_key`), а `asset` и
  `finding` — на журнал практики / отчёт, где они появились. Тогда обратные ссылки актива
  показывают **все находки по нему** — готовый список того, что владелец должен починить, и заодно
  карту, какие активы «горячие».
- **Связи предпочтительнее папок.** Неглубокое дерево папок плюс плотные связи бьёт глубокую вложенность.

## Карты контента (MOC)

Веди `OSINT MOC.md` как парадную дверь. Структурируй её по модели фаз навыка `osint-research`, чтобы
хранилище отражало метод:

```markdown
# OSINT MOC

## Метод
- [[Confidence grading A-B-C-D]] · [[Source independence]] · [[Minimization]]
- [[osint-research phase model]]

## Техники по фазам
### Сбор
- [[Advanced search operators]] · [[Web archive recovery]]
### Инфраструктура
- [[WHOIS-RDAP lookup]] · [[Certificate Transparency logs]] · [[Passive DNS]]
### Медиа и геолокация
- [[Reverse image geolocation]] · [[Chronolocation from shadows]]
### Верификация
- [[Namesake resolution]] · [[Media authenticity checks]]

## Журнал практики
- [[2026-09-30 Geo CTF - harbor photo]]

## Инструменты
- (связаны из заметок о техниках)
```

Добавляй строку в соответствующий раздел MOC всякий раз, когда создаёшь заметку. Тематическую
MOC (например, `Geolocation MOC.md`) стоит выделить отдельно, как только кластер разрастётся
примерно за 8 заметок.

## Рабочий процесс: превращаем прогон в заметки

После расследования `osint-research` или практического упражнения:
1. Сохрани отчёт по `osint-research/assets/report-template.md` → заметка `report`.
2. Для каждой **новой** техники/инструмента/источника, которые ты использовал, создай или обнови её заметку.
3. Напиши короткий `practice-log`: в чём была задача, какие техники сработали, что поставило тебя
   в тупик, и `ethics_check`. Свяжи всё викиссылками.
4. Добавь новые заметки в `OSINT MOC.md`.
5. Если у заметки о технике теперь 3+ обратных ссылки из журналов практики, повысь её `status` до
   `evergreen` — ты доказал, что умеешь ею пользоваться.

## Рабочий процесс: конспект лекции

1. Извлеки текст слайдов (`pdftotext` или PyMuPDF); слайды-картинки отрендерь в PNG и посмотри — в них часто схемы.
2. Создай `Лекции/Лекция NN — <тема>.md` (`type: lecture`): «О чём лекция» → блоки по смыслу (не по слайдам) →
   «Главное для практики» → ДЗ → «Связи».
3. Наступательные темы (sock puppets, обход защит, утечки) — только на уровне концепции и распознавания, с пометкой «вне рамок».
4. Если номер/тема в PDF расходится с программой курса — пометь это в заметке, а не «исправляй» молча.
5. Добавь лекцию в раздел «Лекции курса» в `OSINT MOC.md`; переносимые методики — в соответствующий навык
   (`osint-research`, `media-verification`, `osint-collection`).

## Соглашения по учёбе

- **Одна идея на заметку.** Заметка `technique` — это единственный метод, а не сборная солянка.
- **Пиши заметку для себя-будущего**, посреди расследования: входные данные, шаги, подводные камни, ограничения.
- **Фиксируй режимы отказа.** «Этот инструмент срезает EXIF» так же ценно, как и то, как EXIF читать.
- **Каждая заметка о практике подтверждает этический gate** (`ethics_check`). Только ты сам /
  согласившийся субъект и цели CTF — см. `osint-research/references/ethics-and-legal.md`.
