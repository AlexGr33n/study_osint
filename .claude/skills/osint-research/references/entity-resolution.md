# Entity resolution и графы связей

Источник: курс «AI для OSINT 2026», лекции 7, 8, 10 (конспекты в хранилище). Загружай на Фазах 2–3,
когда нужно решить «это одна сущность или разные?» и строить граф людей/компаний/активов.
Дополняет «Разрешение личности» и «Правило трёх» из `verification.md` и граф активов из `tradecraft.md`.

## Якоря идентичности

| Сильные (идентифицируют) | Слабые (только поддерживают) |
|---|---|
| email, телефон (E.164), код ЕДРПОУ / регистрационный номер, крипто-кошелёк, хэш фото, иногда стабильный ник | имя, должность, локация, геолокация IP, privacy-WHOIS, `abuse@регистратора`, совпадение по имени между базами |

**Правило 2+:** слияние записей требует **≥ 2 независимых сильных якорей**. С правилом трёх
стыкуется так: 2 сильных = атрибуция; 1 сильный + 1 слабый = рабочая гипотеза; одни слабые — минимум три,
и всё равно не слияние, а ребро-гипотеза.

## Чеклист коллизии (тёзки, совпадения ников)

1. Совпадают ли компания/сфера, география, возраст/фото?
2. Есть ли ≥ 2 независимых факта, связывающих записи?
3. Проверена ли гипотеза «это другой человек»?

**При сомнении — не сливать.** Два узла + ребро `POSSIBLY_SAME_AS {verified: false}`. Противоречия полей —
флаг `conflicted` и список `contradictions` с id источников. Решает третий независимый источник.

## Уверенность — из источников, а не из уверенности модели

| Основание | Уровень | Грейд |
|---|---|---|
| детерминированный матч по сильному якорю (тот же ЕДРПОУ, email, телефон) | 9–10 | A |
| 2+ независимых источника | 7–8 | A/B |
| 1 надёжный источник | 5–6 | B |
| косвенные признаки | 3–4 | C |
| только вывод агента / спекуляция | 1–2 | D, в отчёт не идёт |

Две копии одной страницы — **один** источник. Дубли из разных агрегаторов ≠ подтверждение: подтверждает
совпадение в независимом первоисточнике (реестр ↔ санкционный список).

## Пайплайн

`сбор → извлечение (NER / regex / LLM) → нормализация → дедупликация → связывание → граф`

- Нормализация: транслитерация имён, телефоны в E.164, даты в ISO 8601 UTC, домены в нижнем регистре.
- Дедупликация: детерминированная по сильным якорям → fuzzy/векторная по слабым только как кандидаты.
- Каждое **ребро — гипотеза** с источником, датой и грейдом; разные типы связей держи слоями
  (multiplex: соцсеть / бизнес / адрес).
- Агент (LLM) **только предлагает** изменения графа; применяет человек, проверенные узлы блокируются.
- Недатированные события — отдельный блок UNDATED в таймлайне, чтобы слух не стал фактом.

## Модель данных: FollowTheMoney (FtM)

Сущность = `{id, schema, properties}`; **связь — тоже сущность** (`Directorship`, `Ownership`, `Family`) со
своими датами и источниками. Формат OpenSanctions и Aleph; утилита `ftm` экспортирует в Neo4j/Gephi.

## Технические пивоты для кластеризации (публичные)

Общий Google Analytics / FB Pixel ID (BuiltWith, SpyOnWeb) · соседи по IP / reverse IP · поддомены из crt.sh ·
история домена (Wayback) · цепочка IP → ASN → CIDR → организация.
**Ловушки:** IP Cloudflare/CDN — не сервер и не владелец; `abuse@регистратора` к лицу не привязывать;
privacy-WHOIS и молодой домен — индикаторы риска, а не атрибуция.

## Анализ графа: метрика под вопрос

| Вопрос | Метрика / алгоритм |
|---|---|
| кто самый связанный | degree (in/out) |
| кто посредник, «мост» между группами | betweenness |
| кто влиятелен (связан с влиятельными) | eigenvector, Katz (α < 1/λ_max, типично 0.85/λ_max), PageRank (d = 0.85) |
| кто быстро достигает всех | closeness |
| какие есть группы | Leiden (предпочтительно) или Louvain; проверь модулярность Q: ≈0 — сообществ нет |

Порядок: компоненты связности → пути между интересующими узлами → сообщества. Не делай выводов по
«клубку» (hairball) — сначала фильтр и слои.

**Стек:** pandas → NetworkX (анализ) → Gephi (визуализация, Statistics → Modularity); постоянное хранение —
Neo4j; готовые графовые среды — Maltego, SpiderFoot, Flowsint.

## Санкции, PEP, офшоры

- **OpenSanctions** (санкции + PEP одной точкой): `/search` → id; `/entities/{id}?nested=true` → связи,
  `first_seen/last_seen`; `/match` → score кандидата. **Score — не вердикт** (0.78 без даты рождения —
  только кандидат). Ключ бесплатный для СМИ/НКО/академии; bulk-данные CC BY-NC; свой сервер — yente.
- **ICIJ OffshoreLeaks** — опубликованные журналистами выдержки; совпадение по имени — слабый якорь.
- Cypher-шаблон коротких путей «санкционный ↔ офшор» (чем короче путь, тем сильнее связь):
  ```cypher
  MATCH p=(s:SanctionedEntity)-[*..5]-(t:Offshore)
  WHERE NONE(x IN nodes(p)[1..-1] WHERE x:Offshore OR x:Address)
  RETURN p LIMIT 10
  ```

## Антипаттерны

1. Слияние по имени (+ городу). Это слабые якоря.
2. Доверять score матчинга или уверенности LLM как вердикту.
3. Считать перепечатки независимыми источниками.
4. Атрибуция по IP за CDN или по контакту регистратора.
5. Выводы по метрике, не соответствующей вопросу (degree ≠ влияние).
