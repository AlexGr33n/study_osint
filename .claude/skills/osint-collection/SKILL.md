# Сбор данных для OSINT: сборщики, пайплайны, мониторинг

Цель автоматизации — **воспроизводимость**, а не скорость: тот же запуск завтра даёт ту же картину
плюс новое. Основа — курс «AI для OSINT 2026», лекции 5 и 10 (конспекты в `study_osint/Лекции/`).
Этический gate и рамки — навык `osint-research` (Фаза 0, `ethics-and-legal.md`); пройди его до первого запроса.

## Перед первым запросом

Ответь письменно (в README сборщика):
1. **Нужны ли эти данные для вопроса?** Минимизация: только поля, нужные для анализа.
2. **Законное основание и ToS?** robots.txt, условия сервиса, GDPR (цель, срок хранения, кто получит доступ).
3. **Кто увидит цели?** Управляемые платформы (Apify, ScrapingBee, Bright Data) видят, что ты собираешь.
4. **Валиден ли ввод?** Название, домен, ИНН/ЕДРПОУ — проверь формат до запроса.

## Выбор метода (сверху вниз, останавливайся на первом рабочем)

1. **Официальный API** — точные поля, ясные лимиты.
2. **RSS / публичное превью** — дёшево, но без истории (RSSHub; `t.me/s/<канал>` — превью публичного канала).
3. **Скрытый JSON-API сайта** — DevTools → Network → XHR; те же данные, что видит браузер.
4. **HTML** — CSS/XPath-селекторы, тесты на сохранённых ответах.
5. **Headless (Playwright)** — только если без браузера страница пустая.

**Если сайт блокирует** (403, CAPTCHA, бан): официальный API → RSS → архив Wayback → честный User-Agent с
паузами → **остановиться**. Обход защиты вне рамок; отказ сайта фиксируется как данные (статус + дата).

## Каноническая запись

Адаптеры платформ отдельно, модель — общая. Минимум полей:

```json
{"id": "sha256(platform + url)", "platform": "", "collector": "", "source_url": "",
 "author": "", "title": "", "text": "", "published_at": "ISO-8601 UTC",
 "collected_at": "ISO-8601 UTC", "query": "", "raw": {}}
```

Правила: даты в **UTC ISO 8601**; dedup по **стабильному id** (`UNIQUE(source, message_id)` + `INSERT OR IGNORE`);
**сырой ответ рядом** с извлечённым; атрибуция (кто, когда, каким скриптом собрал); неочищаемый аудит-лог.
Хранилище: SQLite/JSONL для одного дела, Elasticsearch для большого корпуса, векторная БД для семантического
поиска. Конфиг целей и состояние (cursor) — отдельно от результатов.

## Надёжность сборщика

- **Инкрементность:** для каждой цели хранить cursor (`last_id` / `min_id` / `before=<id>`). Двигать cursor
  **только после успешной записи**; после рестарта продолжать с него. Отдельно проверять непрерывность по датам
  («дыры»).
- **Вежливость:** ~1 запрос в 2 с, ≤ 2 соединений на домен; семафор для параллели.
- **429 / лимиты:** экспоненциальный backoff с jitter (1→2→4→8 с; `tenacity.wait_exponential`), уважать
  `Retry-After`. Дневной бюджет на ключ — запрос списывается **до** попытки; при исчерпании — soft-defer цели, не ошибка.
- **Кэшируй дорогие операции** (resolve, lookup). Причину бана **измеряй по логам**, а не угадывай
  (в кейсе курса Telegram банил за объём resolve, а не за частоту).
- **Классификация ошибок:** 403 «нет доступа» — пропустить без штрафа; 401 — токен недействителен, пометить;
  429 — кулдаун только этого ключа; прочие 4xx (кроме 409) — пропустить навсегда; 409 и 5xx — повторить позже.
  Всё — в журнал событий.
- **Тихие поломки:** метрика «сколько собрано за прогон», алерт на 0 записей или пустые поля, тесты парсера на
  сохранённых ответах (вёрстка меняется молча).
- **Секреты** — в `.env`, не в коде и не в заметках; храни токен сессии, а не пароль (утечка токена = полный доступ).
- **Пределы полноты фиксируй явно:** каналы отдают историю, E2E-группы — только с момента вступления.

## Обогащение (публичные источники)

| Источник | Что даёт | Замечание |
|---|---|---|
| OpenSanctions `/search`, `/entities/{id}?nested=true`, `/match` | санкции, PEP, связи | score — кандидат, не вердикт; ключ бесплатен для СМИ/НКО/академии |
| crt.sh `?q=%25.{domain}&output=json` | поддомены из CT | без ключа |
| ip-api | гео/ASN | грейд C, не атрибуция |
| Wayback CDX | история страницы | запросы раскрывают, что ты изучаешь |
| ЕДР (data.gov.ua), OpenCorporates, GLEIF, Wikidata | реестры | первичные источники |

Энричеры — через **allowlist доменов**, с таймаутом и лимитом размера ответа; ключи — в хранилище секретов.

## LLM поверх собранного

LLM работает **только над уже собранным**; внешний текст подаётся в тегах как данные (защита от injection).
Ответ — JSON: `overall_risk`, `confidence`, `status_changes`, `red_flags` (каждый привязан к полю досье),
`recommendation`, `next_steps`. Вместо выдумки — «не установлено». Шаблоны и журнал AI-шагов —
`osint-research/references/ai-assisted.md`.

## Мониторинг и алерты

Схема: пайплайн + планировщик (cron / APScheduler / n8n Schedule, каждые 30–60 мин) + таблица `seen` в SQLite.
**Новое** = прошло дедупликацию; **исчезнувшее** = сравнение со snapshot.

Сигналы, на которые стоит алертить:
- новый материал по ключевым словам;
- новая санкционная запись или связь (`last_change` в OpenSanctions);
- новый поддомен в crt.sh;
- изменение снимка Wayback или карточки в реестре;
- всплеск > N записей в час из одного источника;
- **0 записей** за прогон (сломался сборщик).

Каналы: заметка в `inbox/` хранилища, email, Telegram-бот. Мониторинг — только публичных источников и
организаций/тем, не частных лиц.

## n8n ↔ Python

| n8n | Python |
|---|---|
| Schedule Trigger | cron / APScheduler |
| HTTP Request | `requests` / `httpx` + `tenacity` |
| HTML Extract | `selectolax` / BeautifulSoup |
| RSS Read | `feedparser` |
| Code / Set | функция-нормализатор в каноническую запись |
| Remove Duplicates | `INSERT OR IGNORE` по `id` |
| AI Agent / LLM | вызов модели с JSON-схемой ответа |
| Write File / Obsidian | запись `.md` в `inbox/` |

Workflow n8n — референс схемы, а не обязательный инструмент: важны каноническая запись, dedup и журнал.

## Отчёт сборщика / дела

1. Объект: идентификаторы, дата сбора (UTC), скрипт/воркфлоу и его версия.
2. Источники с датами и статусами (включая отказы).
3. Сущности и связи (FollowTheMoney, см. `osint-research/references/entity-resolution.md`).
4. AI-анализ в JSON.
5. **Пробелы:** что не собрано и почему (блок, лимит, E2E, ToS).

Раскладка в хранилище: `inbox/`, `raw/`, `entities/`, `reports/`, `attachments/`.
Критерий: вывод воспроизводится другим человеком по твоим шагам.

## OPSEC сбора

- Отдельный контур: VM или отдельный профиль, отдельные ключи и аккаунты под исследование.
- Проверяй **фактический исходящий IP** перед прогоном — клиент может тихо идти мимо прокси.
  Прокси скрывает только IP, но не аккаунт, cookies и User-Agent.

## Шаблон ДЗ «сборщик одной соцсети» (лекция 5)

Безопасный выбор платформы в рамках хранилища: **RSS, Mastodon, Reddit API, публичный TG-канал через превью**.
Обязательно: инкрементный сбор по cursor, каноническая запись в SQLite/JSONL, пейсинг и backoff на 429,
dedup и устойчивость к сбоям, `.env` + README + `requirements.txt`, ≥ 200 записей, отчёт 0.5–1 стр. о
встреченных лимитах. Вес оценки: инкрементность и dedup 25 %, лимиты и ошибки 25 %, модель 20 %,
код/README 20 %, отчёт 10 %.
