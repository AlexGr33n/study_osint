# Учебные навыки OSINT

Навыки для этого учебного хранилища, адаптированные из **принципов** двух источников —
[smixs/osint-skill](https://github.com/smixs/osint-skill) и
[elementalsouls/Claude-OSINT](https://github.com/elementalsouls/Claude-OSINT) — переписанные под
**этику прежде всего, авторизацию через gate и обучающий** контекст. Из второго источника
портированы только **методология и дисциплина**; наступательный арсенал намеренно оставлен
вне рамок навыка (см. разделы ниже).

## Принципы из первого источника — smixs/osint-skill (сильные стороны)

- **Конвейер по фазам** — воспроизводимая структура от вопроса до отчёта.
- **Лестница эскалации** — сначала дёшево/быстро/открыто, глубоко/тяжело только по необходимости.
- **Грейд достоверности (A/B/C/D)** — каждый факт несёт грейд и свои источники.
- **Перекрёстная проверка и разрешение однофамильцев** — доказывай личность до атрибуции.
- **Рекурсивная самооценка** — оценка покрытия и глубины, останавливайся на убывающей отдаче.
- **Прогрессивное раскрытие** — короткий SKILL.md, детали подгружаются из `references/` по требованию.
- **Параллельный сбор** — разворачивай работу вширь, а суждение держи в центре.

## Что портировано из второго источника — Claude-OSINT (методология и дисциплина)

Из [elementalsouls/Claude-OSINT](https://github.com/elementalsouls/Claude-OSINT) взяты только
**методология и дисциплина**, переосмысленные в защитной/владельческой рамке: находки — это то, что
владелец актива должен починить, а не шаги для атаки. Никакого наступательного how-to. Портировано:

- **Карточка находки (критичность × достоверность)** — каждая находка структурирована: что найдено,
  насколько это критично (критичность: инфо / низкая / средняя / высокая / критическая) и на каком грейде
  достоверности (A/B/C/D) стоит утверждение, плюс **рекомендация по устранению** для владельца актива.
- **Правило трёх и пути апгрейда достоверности** — сколько независимых источников и какого рода нужно,
  чтобы поднять утверждение по лестнице грейдов (D/C → B → A).
- **Граф активов** — типизированные активы (домен, хост, сервис, аккаунт и т.п.) и связи между ними
  как структура наблюдения поверхности атаки.
- **Гигиена доказательств и цепочка происхождения (chain of custody)** — фиксация находок с UTC-таймштампом
  и SHA-256-хешем, чтобы происхождение (provenance) можно было проверить и воспроизвести.
- **Модель заметности (detectability) и лестница отступления (back-off ladder)** — оценивай, насколько
  наблюдение заметно (низкая / средняя / высокая), и отступай к более пассивным методам, а не наращивай нажим.
- **Бюджет времени / профиль работы** — заранее фиксируй, сколько времени и какой глубины заслуживает вопрос.
- **Авторизованный трек поверхности атаки — только обнаружение (discover-only)** — стадии затравка (seed) →
  расширение активов → обогащение → анализ уязвимой поверхности → схождение → отчётность; заканчивается на
  пассивном/публичном наблюдении. «Активная проверка» (active validation) и эксплуатация — вне рамок навыка.
- **Усиленные правила взаимодействия (RoE)** — более строгие ограничители авторизации, рамок (scope) и
  минимизации данных; устойчивость коннекторов при опоре на внешние источники.

Детали — в `references/tradecraft.md` (карточка находки, гигиена доказательств, заметность, лестница
отступления) и `references/attack-surface.md` (трек поверхности атаки, только обнаружение).

## Что намеренно НЕ портировано (осталось вне рамок)

Claude-OSINT — инструмент с наступательным уклоном. Его «оружейные» части перенесены **не были**, потому
что наш навык — **этичный, учебный, только обнаружение (discover-only)**:

- Конкретные **probe-пути** и wordlists для перебора.
- **Secret-регексы** и извлечение секретов.
- **Перечисление пользователей** (user-enum).
- **Валидаторы учётных данных** (endpoint-ы проверки кредов, подбор и отправка кредов).
- Работа с **плейнтекст-паролями из утечек** (breach × identity для подбора паролей).
- **Списки целей для фишинга / credential-stuffing** и per-person dossier для spear-phishing.
- **Активная эксплуатация** и обход контроля доступа.

Где источник предполагал такое действие, у нас на его месте стоит **граница**: это вне рамок навыка,
возможно только с письменной авторизацией и вне OSINT. Категории exposure (открытый `.env`, листящаяся
облачная корзина, `DMARC p=none`, устаревший аплайенс на KEV) остаются как **категории находок** для
владельца актива — без шагов эксплуатации.

## Что намеренно изменено (и почему)

Источник ориентирован на скрытое профилирование **конкретных частных лиц**. Эти
части имеют двойное назначение для слежки и были **удалены или переосмыслены**:

- **Добавлен жёсткий gate авторизации** (цель + рамки (scope) + законный публичный доступ) на Фазе 0.
- **Убран сбор личных сообщений** (личка в Telegram/по email — это не открытые источники).
- **Убран обход контроля доступа** (CAPTCHA/authwall/уход от прокси → вне рамок (scope)).
- **Переосмыслено «психопрофиль → точки входа»** — никакого профилирования частных людей, чтобы
  подойти к ним. Поведенческий/авторский анализ остаётся только как *атрибуционные гипотезы с оговорками*
  для работы с дезинформацией/атрибуцией.
- **Добавлен `ethics-and-legal.md`** как первый reference и поле `ethics_check` в каждой
  заметке практики.
- **Рекомендована самооценка цифрового следа** (свой / согласный коллега / цели CTF) как
  способ *учить* каждую технику.

Легитимные применения, которые поддерживает этот набор: практика CTF и разведки, threat intelligence,
исследования безопасности, журналистика, корпоративная проверка контрагентов (due diligence) и проверка
собственного цифрового следа.

## Использование с Claude Code

Навыки лежат в `.claude/skills/` и подхватываются Claude Code автоматически: срабатывают по описанию
или вызываются явно (`/osint-research`, `/media-verification` …). Для другого агента скопируй папку
навыка в его каталог skills. Навыки используют только стандартные инструменты
(встроенные веб-поиск/загрузка, плюс любые исследовательские API, которые ты явно авторизуешь).
